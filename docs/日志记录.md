## 1. 背景与问题

2026-08-21 DeepSeek 厂商 **canvas Key** 单日 **3,549 次**调用，但平台侧：

| 数据源 | 8/21 数量 | 能否解释 canvas Key |
|---|---|---|
| `GatewayRequestLog`（DEEPSEEK 成功） | 38 | 否（走 bilibili Key） |
| `CanvasGenerationTask`（TEXT） | 38 | 否（与 Gateway 一致） |
| `PlatformErrorLog` | 极少 | 否（只记失败） |
| 厂商控制台 canvas Key | 3,549 | —（无请求级明细） |

**根因**：历史 `DEEPSEEK_API_KEY` env → `api.deepseek.com` **直连**，绕过 Gateway 与所有任务表；成功调用 **零留痕**。

**本次加固目标**：同类事件 **当天可感知**（熔断 + 告警），直连路径 **必留实例与 key 指纹**，次日 **对账兜底**。

---

## 2. 日志分层（看什么、去哪看）

| 层 | 存储 | 入口 | 记什么 | 不记什么 |
|---|---|---|---|---|
| **平台错误日志** | `PlatformErrorLog` | Book `/admin/errors` | 失败、哨兵、对账差异、保险丝熔断、直连审计 | 成功 Gateway 调用明细 |
| **Gateway 请求日志** | `GatewayRequestLog` | Gateway `:3005` Logs | 经 Gateway 的每次 AI 调用（成功+失败） | 业务层 env 直连 |
| **Canvas 任务** | `CanvasGenerationTask` | DB / 排查脚本 | 每次 Canvas LLM/生图/生视频任务 | 直连厂商 |
| **厂商账单** | DeepSeek CSV | Finance `/admin/usage-management` | 按 Key/模型/日聚合 | 来源 IP、调用栈 |

**原则**：平台错误日志 ≠ Gateway 日志；前者是 **运维告警与异常聚合**，后者是 **计费与对账真源**。

## 3. PlatformErrorLog 写入规则

实现：`book-mall/lib/platform-error-log.ts`

- **fire-and-forget**：不阻塞主流程
- **5 分钟 fingerprint 合并**：相同错误合并 `occurrenceCount`，不刷屏
- **统一实例指纹**：每条 `context.runtime` 含 `host` / `pid` / `commitSha` / `instanceLabel`（`APP_INSTANCE_LABEL`）

### 3.1 来源（source）

| source | 含义 |
|---|---|
| `CANVAS` | Canvas 任务 FAILED |
| `GATEWAY` | Gateway 请求 FAILED、模型日上限熔断 |
| `SYSTEM` | env 哨兵、用量对账差异、直连出口审计 |
| `STORY` / `BOOK` / `TOOL` | 其它子站（预留） |

### 3.2 管理后台用法

1. 打开 **`/admin/errors`**
2. 筛 **来源**（CANVAS / GATEWAY / SYSTEM）
3. 勾选 **仅未处理**；按 `occurrenceCount` 看反复失败
4. 展开行看 `context`：`projectId` / `nodeId` / `modelKey` / `gatewayLogId` / **`runtime.host`**

## 4. 加固机制一览（2026-08-24）

| ID | code | 触发 | severity | 开关 |
|---|---|---|---|---|
| PL-101 | `LEGACY_VENDOR_ENV` | boot 检出废弃直连 env（`DEEPSEEK_API_KEY`） | ERROR | 恒开 |
| PL-102 | `USAGE_RECON_MISMATCH` | 常驻调度：昨日平台任务 vs Gateway 差异 | WARN | **`/admin/settings`** 开关 |
| PL-103 | `USAGE_RECON_MISMATCH` | Finance 上传厂商 CSV 后对账差异 | WARN/ERROR | 无 |
| PL-104 | `VENDOR_DIRECT_EGRESS` | 业务层 `OpenAiCompatGateway` 命中已知厂商域名 | WARN | **`/admin/settings`** 阻断名单 |
| PL-105 | `MODEL_DAILY_LIMIT` | 单 model 当日 Gateway 调用达上限 | ERROR + 429 | **`/admin/settings`** |

### 4.1 boot env 哨兵（PL-101）

- **代码**：`lib/gateway/legacy-vendor-env-sentinel.ts` · `instrumentation.ts`
- **废弃清单**：`DEEPSEEK_API_KEY`（可扩展 `LEGACY_VENDOR_ENV_VARS`）
- **落库字段**：`context.envVar`、`context.keyFingerprint`（sha256 前 12 位，**不含 key 原文**）
- **运维**：部署后在 `/admin/errors` 搜 `LEGACY_VENDOR_ENV`，`runtime.host` 即嫌疑实例

### 4.2 常驻用量对账（PL-102）

- **代码**：`lib/gateway/usage-recon-scheduler.ts`
- **节奏**：每 30min 检查；**CST 01:00 后**审计 **昨日**（给 finalize 留窗口）
- **对比**：`CanvasGenerationTask` / `StoryGenerationTask` / `ToolUsageEvent` vs `GatewayRequestLog`（按应用）
- **告警**：`MISSING_GATEWAY`（平台多、Gateway 少）/ `ORPHAN_GATEWAY`（Gateway 多、平台少）

### 4.3 CSV 对账即时告警（PL-103）

- **代码**：`lib/finance/usage-daily/report-vendor-recon-alerts.ts`
- **触发**：Finance `/admin/usage-management` POST 上传 DeepSeek CSV 后
- **重点**：`MISSING_PLATFORM` = 厂商有、Gateway 无 → **直连嫌疑**（与 canvas Key 事件同型）

### 4.4 业务层直连出口审计（PL-104）

- **代码**：`lib/gateway/vendor-egress-audit.ts` · 挂在 `OpenAiCompatGateway.chat` / `createImageTask`
- **已知厂商 host**：`api.deepseek.com`、`dashscope.aliyuncs.com`、`api.moonshot.cn`、`ark.cn-beijing.volces.com` 等
- **落库**：`vendorHost` / `modelKey` / `keyFingerprint` / `caller` / 调用栈摘要
- **硬阻断**（可选）：`VENDOR_DIRECT_BLOCK_HOSTS=api.deepseek.com`

### 4.5 单模型日调用上限 · 保险丝（PL-105）

- **代码**：`lib/gateway/model-daily-limit.ts` · 入口 `createRequestLog`（全 Gateway 路径）
- **配置**：**`/admin/settings`（PlatformConfig）> env > 默认**；后台改后约 30s 生效
- **计数**：同一 `model` + CST 业务日，`GatewayRequestLog.submittedAt` 计数（**含 FAILED**）
- **动作**：达上限 → **429** + `MODEL_DAILY_LIMIT` 落库
- **索引**：迁移 `20260824210000_gateway_log_model_submitted_idx`

## 5. 配置（管理后台）

**统一入口：Book `/admin/settings`（日志与保险丝配置）**，存 `PlatformConfig`；环境变量仅作 DB 不可用时回退。

| 配置项 | 后台字段 | 默认 | 说明 |
|---|---|---|---|
| 单模型日上限 | `modelDailyLimit` | `300` | `0` = **关闭**整个保险丝 |
| 按模型覆盖 | `modelDailyLimitOverrides` | `{}` | JSON 对象，如 `{"deepseek-v4-flash":1000,"kling-x":0}`（`0`=该模型不限） |
| 直连阻断名单 | `vendorDirectBlockHosts` | `[]` | host 数组；命中则 `VENDOR_DIRECT_BLOCKED` 并拒绝；空=仅审计 |
| 常驻对账开关 | `usageReconEnabled` | 开 | 关闭后不再每日自动审计 |
| 对账间隔 | `usageReconIntervalMin` | `30` | 分钟 |

**对应 env 回退**（后台未配置 / DB 不可用时）：`GATEWAY_MODEL_DAILY_LIMIT`、`GATEWAY_MODEL_DAILY_LIMIT_OVERRIDES`、`VENDOR_DIRECT_BLOCK_HOSTS`、`USAGE_RECON_RESIDENT`、`USAGE_RECON_INTERVAL_MS`。

**实例标识**（`context.runtime`）：`APP_INSTANCE_LABEL`（如 `tencent-book-mall-prod`）。

**禁止**：在 book-mall `.env` 配置 `DEEPSEEK_API_KEY`（见 `audit-legacy-deepseek-canvas-key.ts`）。

## 6. 排查手册

### 6.1 厂商 Key 用量异常飙高

1. `/admin/errors` → 筛 SYSTEM → 看 `LEGACY_VENDOR_ENV` / `VENDOR_DIRECT_EGRESS` / `USAGE_RECON_MISMATCH`
2. Finance `/admin/usage-management` → 上传昨日 DeepSeek CSV → 看 `MISSING_PLATFORM` 行
3. Book `/admin` 驾驶舱 → 用量审计对比（平台 vs Gateway）
4. 脚本：`tsx scripts/deepseek-forensics-hour.ts YYYY-MM-DD HH`（按小时对齐 Canvas 任务与 Gateway）
5. 脚本：`tsx scripts/audit-legacy-deepseek-canvas-key.ts`（env + Gateway 凭证）

### 6.2 某模型突然被 429

1. `/admin/errors` → 搜 `MODEL_DAILY_LIMIT`
2. 看 `context.modelKey` / `usedCount` / `dailyLimit`
3. **`/admin/settings`** 调「单模型日上限」或「按模型覆盖」
4. 关闭保险丝：`/admin/settings` 把上限设为 `0`

### 6.3 多容器并存、不知哪台在调

看任意 PlatformErrorLog 行的 `context.runtime`：

```json
{
  "host": "container-abc123",
  "pid": 42,
  "commitSha": "a1b2c3d4e5f6",
  "instanceLabel": "tencent-book-mall-prod"
}
```
