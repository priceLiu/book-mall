# 画布组节点重叠穿插的问题

> **状态**：问题已分析 · **实现决策：暂缓**（2026-10-17）· 优先记录方案 A / B  
> **管理入口**：Book [`/admin/pending-features`](http://localhost:3000/admin/pending-features) → **待处理** · 从 docs 导入或 seed `CVL-*`  
> **范围**：`canvas-web` · LibTV 画布（Pro2 / 分镜视频 1.0）· React Flow 媒体组与预设组  
> **关联代码**：`libtv-manipulation-layer.ts` · `flow-canvas.tsx` · `normalize-graph-nodes.ts` · `globals.css` · `canvas-edge-layer-z.ts`

---

## 1. 现象

| 场景 | 表现 |
|------|------|
| 多个「文生视频」等预设组重叠 | 组壳、组内视频/文本/图片**交错**，不像一个整体 |
| 拖组到另一组上方 | 有时正常，有时**后创建的组**或**第二次拖动的组**与子节点穿插 |
| 图片拖入组 | 拖入过程中与其它组穿插；曾出现组底变「全黑」（`.is-drop-target` CSS 覆盖底色，已局部修复） |
| 拖组 | 曾出现组内节点消失（组节点置后破坏 RF 父子顺序 / 组壳 z 高于子节点，已局部修复） |

**产品目标（讨论定稿）**：**选中 ≡ 拖动** — 激活时，**节点 / 组 / 框选 / 相关连线** 作为 **manipulation bundle** 整体置顶。

---

## 2. 根因（技术）

LibTV 画布叠加**不是「一组一个 stacking 单元」**，而是多套规则并存：

1. **CSS 固定档**（`canvas-web/app/globals.css`）  
   - 组壳约 **5**，子节点约 **22**，选中/操纵约 **1200～1202**，连线 SVG 约 **12 / 1199**。

2. **React Flow 节点顺序**（`sortNodesForReactFlow`）  
   - 扁平三段：`[ 所有 group 壳 ] + [ 根节点 ] + [ 所有组的子节点 ]`。  
   - 组壳与子节点**不在同一 DOM 父级**；默认 **子(22) > 壳(5)**，故 **A 组子节点可画在 B 组绿框之上**。

3. **临时操纵层**（`applyLibtvManipulationLayerToNodes`）  
   - 仅在有 **选中 / draggingNodeId / hoverGroupId** 时抬层；松手且未选中后回到 5/22 + 数组顺序。

4. **已做补丁（非统一模型）**  
   - 操纵 bundle、拖入悬停抬组、单节点 drag z=1202、组拖松手 `bumpLibtvGroupRenderOrderToFront`、store↔RF 合并后重算 z 等。  
   - **无法保证**多组重叠在未激活时仍整齐。

---

## 3. 方案 A · 仅激活时置顶（已选方向 · **暂缓实现**）

### 3.1 语义

- **激活** = 点选、框选、拖动、（可选）拖入组悬停。  
- **激活期间**：bundle 内组壳 + 全部 sibling 子节点 + 相关边 → 统一高于未激活节点（例如壳 1200、子 1201、拖动中节点 1202、边 1199）。  
- **取消选中 / 松手后**：不承诺持久谁在上；重叠区域可能再次穿插（产品接受）。

### 3.2 实现要点（将来做）

| 项 | 说明 |
|----|------|
| 单一入口 | 所有 RF 选中/拖动/框选路径调用同一 `resolveManipulationBundle` + `applyLayer` |
| 非激活上限 | 全局未激活 ≤ 22（或固定 idle 档），激活包 ≥ 1200 |
| 框选 | 多个组/节点 → 多个 `activeGroupId` 或等价 bundle 集合 |
| 拖组 | 组壳不得高于本组子；**禁止**仅把 group 节点移到数组末尾 |
| 拖单节点进组 | `hoverGroupIds` 抬悬停组；拖动节点 1202 |
| 边 | `edgeInManipulationBundle` 与节点 bundle 同一规则 |
| 组拖 | **不**对 group 使用 `hoverGroupIds` 共抬（避免两组同 z 靠 DOM 打架） |

### 3.3 影响面（相对 B 较小）

- **会动**：LibTV 画布 z/class、边层、`flow-canvas` 与 store↔RF 同步。  
- **基本不动**：graph 持久化字段、spawn/复制默认层级、旧项目迁移。  
- **需注意**：连线可见性公式、connecting 模式、spawn 后未选中时的默认顺序。

---

## 4. 方案 B · 持久 stackRank（未选 · 备选）

### 4.1 语义

- 每个 **stack 单元**（组 = 壳 + 全体子；独立节点 = 自身）有整数 `stackRank`。  
- **激活**时 bump 到 `max+1`（框选多组：共顶或依次 +1，需产品定一条）。  
- **松手后仍保持**「最后激活者在最上」，类似 Figma bring-to-front。

### 4.2 实现要点

- `GroupNodeData` 或节点级字段 + 迁移旧图（按当前 nodes 顺序初始化）。  
- z 由 rank 推导：`壳 = base + rank×step`，`子 = base + rank×step + 1`，保证 **高 rank 壳 > 低 rank 全部子**。  
- undo/redo、复制组、spawn 新组默认 rank。  
- 边 z 与 rank / bundle 统一。

### 4.3 影响面

- 持久化、迁移、seed、duplicate、relayout 与 rank 一致性；测试面大于 A。
