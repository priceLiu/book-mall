# 模型与应用管理（模型调用地图）

> **状态**：待做功能 · 需求与设计定稿（Phase 1 起尚未开发）  
> **关联**：`book-mall/doc/product/model-operations-center.md` · `book-mall/doc/tech/gateway-unified-model-registry.md`  
> **管理入口（目标）**：Finance → `/admin/platform-models` 新增 Tab「调用地图」，或独立页 `/admin/model-invocation-map`

---

## 1. 背景与问题

全站 AI 模型配置来源分散，运营与研发难以回答：

- 某个**应用**、某个**页面/模块**、某个**功能点**分别用了哪些模型？
- 每个调用点一共接入了**多少种**模型（可选 vs 固定）？
- 用户选模、系统固定（如 AI 小智）、代码写死预设节点，能否**统一查看与配置**？

### 现状（已有 vs 缺失）

| 能力 | 位置 | 粒度 | 缺失 |
|------|------|------|------|
| 模型运营中心 | Finance `/admin/platform-models` | `appTag` + `sceneKey` | 非页面级；sceneKey 手填；不管固定模型 |
| AppModelShelf（L5） | 同上 · 应用分发 Tab | 用户**可选**模型列表 | 不管 embedding、兜底链、预设写死 |
| Gateway 日志 `clientPage` | `GatewayRequestLog` | 每次调用 | 无登记册、不可配置 |
| 代码白名单 | `model-ops-seed-config.ts` 等 | scene 级 | 与 DB 双轨，易漂移 |
| AI 小智 | `platform-assistant/config.ts` + env | 固定 + fallback | 无管理界面 |
| Gateway 凭证 | `:3005/dashboard/models` | 厂商 Key | 非功能映射 |

**结论**：需要在本体「模型运营中心」之上，新增 **L6 调用点绑定 + 调用地图**，实现**全站可见、分级可配**。

## 2. 目标

1. **全面**：每个应用 → 每个页面/模块 → 每个 AI 调用点 → 模型数量与清单一目了然。
2. **可配置**：运营可改系统固定模型、默认模型、上架列表；减少改代码/env。
3. **可校验**：配置与 Gateway 日志实际用量对比，发现漂移（配置允许 N 种，日志出现第 N+1 种）。
4. **渐进落地**：先只读地图 + 统计，再接入运行时配置。

### 非目标（首期不做）

- 替换 Gateway 凭证绑定 UI。
- 在运营中心编辑 `paramsSchema`（仍由代码 KNOWN 映射 enrich）。
- 一次性删除所有前端 `*_MODEL_KEYS` 硬编码（Phase 3）。

## 3. 核心概念：调用点（InvocationPoint）

**调用点** = 全站 AI 能力的最小管理单元。

### ID 格式

```
{appTag}/{surface}/{featureKey}
```

| 字段 | 含义 | 示例 |
|------|------|------|
| `appTag` | 子应用 | `canvas` · `ecom` · `platform` |
| `surface` | 页面/产品模块（非 URL 碎片） | `pro2-hub` · `text-to-image` |
| `featureKey` | 模块内具体 AI 能力 | `story-outline-llm` · `chat` |

示例：

| invocationKey | 说明 |
|---------------|------|
| `canvas/pro2-hub/story-outline-llm` | Pro2 故事大纲 LLM |
| `canvas/pro2-hub/frame-image` | Pro2 分镜生图 |
| `tool/text-to-image/generate` | 工具站文生图 |
| `platform/assistant/chat` | AI 小智对话 |
| `platform/assistant/rag-embed` | 小智 RAG 向量 |
| `ecom/storyboard/panel-video` | 电商分镜单格视频 |

### 与现有 `sceneKey` / `clientPage` 的关系

| 概念 | 用途 |
|------|------|
| `sceneKey` | 用户选模列表（L5 AppModelShelf）的索引键，如 `pro2-llm` |
| `clientPage` | Gateway 日志归因，如 `platform-assistant/chat` |
| `invocationKey` | 运营配置主键；可关联 `sceneKeyRef` 与 `clientPagePattern` |

## 5. 三类调用与绑定模式

| 类型 | 典型场景 | `bindingMode` | 用户能否换模 |
|------|----------|---------------|--------------|
| **A. 用户选模** | Canvas EnginePicker、电商 StoryboardModelPicker | `ALLOWLIST`（指向 L5 `sceneKey`） | 能 |
| **B. 系统固定** | AI 小智、AI 热闻、RAG embedding | `FIXED` 或 `FALLBACK_CHAIN` | 不能 |
| **C. 预设写死** | 画布 spawn 固定 modelKey 节点 | `FIXED`（`configSource=CODE` 迁入 DB） | 不能 |

### 数据模型（示意 · Phase 2 落库）

```prisma
enum InvocationBindingMode {
  USER_PICK      // 用户从 shelf 选（等同 ALLOWLIST + default）
  ALLOWLIST      // 关联 sceneKey，列表来自 AppModelShelf
  FIXED          // 单一 modelKey
  FALLBACK_CHAIN // 有序尝试，如 deepseek → qwen3.5-flash
}

model ModelInvocationBinding {
  id                String   @id @default(cuid())
  invocationKey     String   @unique
  appTag            String
  surface           String
  featureKey        String
  displayName       String   // 「AI 小智 · 对话」
  role              CanvasModelRole  // LLM | IMAGE | VIDEO | EMBED | AUDIO
  bindingMode       InvocationBindingMode

  sceneKeyRef       String?  // ALLOWLIST / USER_PICK
  fixedModelKey     String?
  fallbackModelKeys String[] // PostgreSQL text[]
  defaultModelKey   String?

  clientPagePattern String?  // 日志匹配，如 platform-assistant/*
  codeRef           String?  // 代码锚点，供 CI 校验
  configSource      String   // DB | ENV | CODE
  status            String   // ACTIVE | DEPRECATED
}
```

## 8. 运行时接入（Phase 2+）

### A 类 · 用户选模

保持现有 API，调用点只存 `sceneKeyRef`：

```
GET /api/sso/tools/gateway/models/registry?app=canvas&role=IMAGE&sceneKey=pro2-image
```

### B 类 · 系统固定（以 AI 小智为例）

```ts
const binding = await resolveInvocationBinding("platform/assistant/chat");
const models = binding.fallbackModelKeys.length
  ? binding.fallbackModelKeys
  : [binding.fixedModelKey];
```

解析顺序：**DB → env → 代码默认**（迁移期）。

### 日志对齐

- 所有 Gateway 调用继续带 `x-gateway-client-page`（已有）。
- 未匹配任何 `clientPagePattern` 的调用 → 运营后台「未登记调用」告警。

建议 API：

- `GET /api/finance/admin/model-invocation-map`
- `GET /api/finance/admin/model-invocation-map/stats?days=30`

## 12. 验收标准

### Phase 1

1. 运营可在后台看到全站调用点清单（应用 × 模块 × 功能 × 模型数）。
2. 每个调用点可跳转查看关联 `sceneKey` 或固定 modelKey 来源（代码路径/doc）。
3. 近 30 天日志统计可展示「实际使用模型数」，与配置不一致时标黄。
4. 文档与 seed 清单一致，新增调用点须更新注册表。

### Phase 2+

5. 修改 AI 小智主模型/兜底链无需改 env（DB 配置生效）。
6. Shelf 下架后，对应 ALLOWLIST 调用点 API 不再返回该模型（沿用 L5 规则）。
