# 一键发布平台（Publisher）

## 1. 需求

### 1.1 产品定位

基于 MultiPost-Extension 开源能力 fork 并深度定制，提供**社交平台一键发布**能力。产品可**独立运营**（自有门户、扩展、桌面端），也可被**电商工具箱**等子应用嵌入调用。

### 1.2 产品形态

| 形态 | 说明 |
|------|------|
| **publisher-web** | 独立门户（端口 3011），登录、注册、内容编辑、发布任务管理 |
| **publisher-extension** | 浏览器扩展（Plasmo / MV3），借用浏览器内平台登录态执行发布 |
| **publisher-desktop** | Electron 桌面端，**多平台账号矩阵**（每个账号独立 session 分区） |

### 1.3 账号与计费

- **账号体系**：与 book-mall 完全统一（同一 User、同一钱包）。
- **注册**：仅在 publisher-web（自有品牌），扩展与桌面端不提供注册。
- **登录**：扩展与桌面端跳转网页登录，长效凭证（90 天滑动续期）回传客户端。
- **计费**：发布动作**不扣积分**；按 `navKey = social-publisher` 收**月度技术服务费**（按账号计费，本轮先预留 navKey 与定价占位）。
- **准入**：生成/发布前检查 `social-publisher` navKey 是否有效。

### 1.4 V1 平台范围

- 小红书、抖音、微博、B 站、微信公众号（公众号若无法全自动则标注半自动）。

### 1.5 关键约束

- 完全脱离 MultiPost 官网（无 ping、无 REST API 回传、无跳转 multipost.app）。
- 扩展与桌面端的**平台登录态不互通**（扩展用 Chrome 登录态，桌面用独立 partition）。
- 网页派发任务以网页身份为准；扩展独立发起以扩展身份为准；userId 不一致时扩展拒绝并提示。
- `TOOLS_SSO_SERVER_SECRET` 不得打入扩展或 Electron 包。

## 2. 解决方案

### 2.1 架构分层

```
平台层 book-mall
  ├── /api/sso/client/*     长效凭证、设备管理
  └── /api/sso/tools/publisher/*  准入、jobTicket

控制台层
  ├── publisher-web（3011）  独立门户
  └── e-commerce-toolkit     一键发布入口

执行器层
  ├── publisher-extension    浏览器扩展
  └── publisher-desktop      Electron 多账号矩阵

共享包
  ├── shared/publisher-sync-core   平台 inject 脚本
  └── shared/publisher-client      认证与任务 SDK
```

### 2.2 认证方案

**网页（publisher-web）**

- 自有 `/login`、`/register`，BFF 转发 book `portal/verify`、`auth/register`、`auth/sms/send`。
- SSO callback：`/auth/sso/callback` 换 tools JWT，存 httpOnly cookie。

**扩展 / 桌面端**

- 仅「登录 / 注册」按钮 → 打开 publisher-web 登录页（带 `client=extension|desktop` 与回调参数）。
- 登录成功后网页 `postMessage`（扩展）或 loopback 回调（桌面）回传 `access_token` + `refresh_token`。
- 续签：`POST /api/sso/client/refresh`（90 天滑动续期）。
- 设备表 `ClientDevice`：支持个人中心「已登录设备」查看与吊销。

**单会话**

- 按 `deviceType`（WEB / EXTENSION / DESKTOP）维度挤下线：同类型再登录才挤掉前一个，跨类型互不影响。

### 2.3 发布任务流

1. 控制台向 book 申请 `POST /api/sso/tools/publisher/jobs` → 校验用户 + navKey → 签发短时 `jobTicket`（含 jobId、userId、platforms、exp）。
2. 控制台 `postMessage` 将 `jobTicket + 内容` 派发给扩展（受信 origin 白名单）。
3. 扩展校验：origin 在白名单、jobTicket 有效、本地登录 userId 与 ticket.userId 一致。
4. 扩展 / 桌面执行 `publisher-sync-core` 平台脚本，回报结果至控制台或直接 POST book（V2）。

**不扣积分**：无 reserve/settle；仅 navKey 准入检查。

### 2.4 桌面端多账号矩阵

- 每个平台账号：`session.fromPartition('persist:acct-<id>')` 独立 Cookie 分区。
- 账号管理：新增、命名、登录状态检测、删除（二次确认）。
- 批量发布：一次内容 → 多账号串行执行 → 汇总结果。

### 2.5 目录与端口

| 目录 | 端口 | 说明 |
|------|------|------|
| publisher-web | 3011 | Next.js 门户 |
| book-mall | 3000 | 平台 API |
| e-commerce-toolkit | 3007 | 嵌入入口 |

### 2.6 实施阶段

| 阶段 | 内容 |
|------|------|
| 0 | 文档、navKey、SSO 登记、dev 编排 |
| 1 | ClientDevice、client auth API、设备管理、单会话改造 |
| 2 | 扩展 fork、去品牌、sync-core、五平台脚本 |
| 3 | Electron 壳、loopback 登录、多账号矩阵 |
| 4 | jobs API、电商工具箱接入 |

### 3.2 遗留与限制

- **ToolServiceFeePlan**：`social-publisher` 月费占位需在管理后台配置定价后才会出现在开通页。
- **平台 DOM 脚本**：扩展内仍使用 MultiPost 原始 inject 逻辑；`publisher-sync-core` 目前为平台元数据注册表，后续需逐步迁移脚本并支持热更新。
- **微信公众号**：标注为半自动（草稿 + 跳转确认发布）。
- **publisher-web 生产部署**：Dockerfile 已添加，CloudBase 服务表待运维登记。
- **扩展/桌面商店发布**：未包含在本轮 CI；需单独打包与审核。

### 3.3 本地启动

```bash
pnpm --dir publisher-web install
pnpm --dir publisher-web dev          # http://localhost:3011
pnpm --dir publisher-extension install
pnpm --dir publisher-extension dev    # Plasmo 开发
pnpm --dir publisher-desktop install && pnpm --dir publisher-desktop dev
```

Book 侧需已配置 `TOOLS_SSO_JWT_SECRET` / `NEXTAUTH_SECRET`（jobTicket 签名）及 `pnpm --dir book-mall db:apply-pending` 已执行。
