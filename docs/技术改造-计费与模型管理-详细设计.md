## 1. 目标与决策基线

| 决策项 | 结论 |
|---|---|
| 架构 | book-mall 单体内部模块化（gateway / finance / pricing / admin），gateway-web、finance-web 保持前端 |
| 计费口径 | 全站统一为 book-mall 单一积分价，前端只读后端结果（废除 tool-web「方案 A」点计价、finance-web 复制公式） |
| 积分兑换率 | `creditExchangeYuan = 0.03`（1 积分抵扣 0.03 元，从 0.04 调整） |
| 加价系数 M | 配置在模型成本表 `ModelCostProfile.marginM`；**视频/图片默认 1.5，其他（文本/音频）默认 1.0**，管理员后台可调 |
| 扣费公式 | `积分 = round(成本 × marginM ÷ 0.03)` |
| 调用日志 | PostgreSQL 原生声明式分区（PARTITION BY RANGE submittedAt 按日），由 gateway 模块写 |
| 平台专用 key | 发放平台专用 key（类型标识），仅内部 `Gateway-Internal` 认证可用，外部 Bearer 拒绝 |
| 技术栈 | Next.js 保留（后续迁 Java，代码层面留边界） |

## 3. 计费口径统一

统一后**唯一扣费真源** = book-mall `credit-account-service`，公式：

```
净成本 C = 成本单价（按 token/尺寸/时长） × (1 − discountRate)
挂牌积分 U = round(C × marginM ÷ creditExchangeYuan)
实扣积分   = U × 用量（千token / 张 / 秒）
```

- `marginM`：视频/图片 = 1.5，文本/音频 = 1.0（模型成本表配置，管理员可调）。
- `creditExchangeYuan`：全局 0.03。

**需废除/同步的第二套口径：**
- `tool-web/lib/tools-scheme-a-pricing.ts` + `config/tools-scheme-a-catalog.json`（点 + retailMultiplier）→ 改读 book-mall 统一积分价接口。
- `finance-web/lib/credit-pricing-formulas.ts`（复制公式）→ 改从 book-mall 拉取，或删除本地点。
- `tool-web/lib/tool-billable-price.ts`、`lib/tool-service-fee/charge-monthly.ts`（已下线）→ 删除。

## 5. api_key 统一调用 + 平台专用 key

### 5.1 现状

- 外部：`Authorization: Bearer sk-gw-...` → `resolveGatewayApiKeyFromBearer`
- 内部：`Authorization: Gateway-Internal {secret}:{apiKeyId}` → `resolveGatewayApiKeyById`
- 现有 `scope`（PERSONAL/PLATFORM）+ `managedByPlatform` 未严格区分调用来源。

### 5.2 平台专用 key 设计

1. 发放一个 `keyType = PLATFORM_ONLY` 的 key（`scope = PLATFORM`），绑定平台厂商凭证池。
2. **仅内部可调**：`resolveGatewayApiKeyById` 放行；`resolveGatewayApiKeyFromBearer` 对 `keyType = PLATFORM_ONLY` 的 key 返回 `null`（→ 401），杜绝外部调用。
3. 平台内部各业务模块（canvas/story/tool/ecom 等）统一用该平台专用 key，通过 `Gateway-Internal` 认证调用 Gateway。
4. 消耗数据、积分账户仍按「api_key → 账户」关联；平台专用 key 关联平台账户（积分统一）。

### 5.3 改造点

| 文件 | 改动 |
|---|---|
| `lib/gateway/api-key-service.ts` | `resolveGatewayApiKeyFromBearer` 增加 keyType 校验，PLATFORM_ONLY 拒绝 |
| `lib/gateway/gateway-v1-auth.ts` | 内部认证保持不变 |
| `lib/gateway/platform-managed-key.ts` / `platform-credential-seed.ts` | 生成/初始化平台专用 key（keyType=PLATFORM_ONLY） |
| 业务模块（canvas/story/tool/ecom 客户端） | 统一改为内部认证 + 平台专用 key，传参校验 |

## 7. 验证方案（重点）

### 7.1 扣费入口验证

1. **静态穷尽扫描**：grep `consumeCredits|reserveCredits|settleReserved|releaseReserved|refundCredits|settleSucceededGatewayLog|refundFailedGatewayLog`，逐一确认每个调用点已走新公式（成本 × marginM ÷ 0.03），无硬编码旧 anchor 0.04 或旧 M。
2. **接口正确性**：
   - 造一个 token 计费模型（如 qwen-turbo，成本 0.002 元/千token），验 `round(0.002 × 1.0 ÷ 0.03) = round(0.0667) = 0`（不足 1 积分的低单价模型需设最低扣 1 积分护栏）。
   - 造一个视频模型（成本 1 元/秒，M=1.5），验 `round(1 × 1.5 ÷ 0.03) = 50` 积分/秒。
3. **并发幂等**：同一 requestId 并发打 10 次扣除接口，验只扣 1 次（V1 修复后）。

### 7.2 api_key 传参验证

1. 各业务模块调用 Gateway 时，验证请求体携带 `model`（含计费类型所需字段：token 的 max_tokens/stream、视频的尺寸/时长、图片的张数）。
2. 平台专用 key：外部 `Bearer` 调用 → 401；内部 `Gateway-Internal` 调用 → 正常。

### 7.3 平台专用 key 验证

- 用平台专用 key 外部 Bearer 调用 → 必须 401。
- 用平台专用 key 内部调用 → 正常路由 + 扣费。
- 普通用户 key 外部 Bearer 调用 → 正常。

## 9. 已确认决策（2026-09-06）

- 低单价模型（成本×M÷0.03 取整后 < 1 积分）：**设「最低扣 1 积分」护栏**，任何成功调用至少扣 1 积分。
- 平台专用 key 账户归属：**挂在管理员账户下**（不单独建平台账户）。
