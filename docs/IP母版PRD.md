| 项目 | 内容 |

## 1. 产品概述

### 1.1 一句话定义
将「一张角色基准图」或「一段角色文字描述」，转化为一份**结构化的 IP 母版模板**（刚性锚点 + 柔性可变项 + 特例放行规则），供下游手办、VI、表情包等生成流程统一读取复用，保证全渠道角色识别不崩坏。

### 1.2 产品定位
- **独立功能模块**：可单独调用（口令触发），单独产出模板；
- **内嵌可选分支**：可嵌入手办 SOP、VI 表情包 SOP 的「上传参考图」步骤，按需生成或读取模板；
- **非强制**：用户可选择不生成模板，沿用原有「直接上传参考图跑图」的旧流程。

### 1.3 与现有系统的关系（既分也合）
```
IP 母版模板生成器（定义「角色骨架」规范，独立可跑）
        │ 产出：IP母版模板（结构化文本，可复用）
        ▼
手办盲盒 SOP（3D实体化执行）──┐
品牌 VI+表情包 SOP（2D品牌化执行）──┴── 各自独立可跑，第一步可读取 IP母版模板作为约束
```

## 2. 背景与问题

| # | 现状痛点 | 影响 |
|---|---|---|
| 1 | 手办、VI 各自以参考图为基础生成，缺结构化约束 | 多载体产出物形象分裂（手办和表情包不像同一个角色） |
| 2 | AI 生图无法像素级复刻比例 | 无统一标准判断「是否崩 IP」 |
| 3 | 传统 VI 规范把所有外观全部锁死 | 不符合新潮 IP 发色/肤色/服饰变体玩法 |
| 4 | 刚性锚点无优先级 | AI 翻车时不知优先保哪个特征 |
| 5 | 模板无版本管理 | 多次迭代后新旧版本混乱 |

## 3. 目标用户与使用场景

### 3.1 目标用户
IP 设计师、品牌运营、潮玩工作室、自媒体博主、接单设计师。

### 3.2 使用场景

## 4. 核心概念定义

| 概念 | 定义 | 说明 |
|---|---|---|
| **刚性锚点** | 角色的识别骨架，不可改动 | 脸型轮廓、头身比、标志性轮廓特征、五官相对排布；**带优先级** |
| **柔性可变项** | 允许自由修改的外观项 | 发色、发型细节、肤色、服饰、配饰、表情、动作；用于盲盒系列、季节款、限定皮肤 |
| **软约束** | 柔性项修改的边界 | 柔性项变更不得破坏角色整体气质风格（可选附加） |
| **特例放行规则** | 特定场景下允许临时突破刚性锚点的白名单 | 默认空白，按需填写（如超大摆件允许临时改头身比） |
| **模板版本** | 模板的版本标识 | 版本号 + 生成时间，多版本保存，默认读取最新版 |

### 4.1 刚性锚点 vs 柔性可变项 判定原则
- **锁「识别骨架」**：改了就认不出是同一个角色的特征 → 刚性锚点；
- **放「皮肤穿搭」**：改了仍是同一角色、可做变体款式的特征 → 柔性可变项。

判定示例（以带星星发饰的 Q 版角色为例）：
- 刚性：圆包子脸型、3 头身比例、星星发饰轮廓形状、五官相对位置；
- 柔性：发色、肤色、服装款式颜色、表情幅度、动作。

## 5. 功能需求详述

### FR-1 图生模板（路径 A）
**输入**：用户上传 1 张角色基准图（支持线稿、立绘、头像、已有手办/VI 产物图）。
**处理**：AI 自动解析图片，提取：
1. 刚性锚点清单（含优先级标注：最高/次）；
2. 柔性可变项清单；
3. 角色基础人设摘要（可选，轻量）。
**输出**：标准格式 IP 母版模板（见第 6 节），进入校对环节（FR-3）。

### FR-2 文生模板（路径 B）
**输入**：用户输入角色文字描述（自然语言，可含品牌名称、风格、特征）。
**处理**：AI 将自然语言整理规范为结构化模板，自动区分刚性锚点 / 柔性可变项 / 特例放行规则。
**输出**：标准格式 IP 母版模板（同 FR-1），进入校对环节（FR-3）。
**规则**：文字描述缺失的信息（如肤色、比例）标记为「待补充」，不编造默认值；用户可跳过，模板留空。

### FR-3 快速校对（轻量，非人工审核）
自动提取后，向用户展示模板文本，允许直接修改后保存。
- 目的：修正 AI 识图误差（AI 可能看错轮廓、误判头身比）；
- 交互：展示模板 → 用户直接编辑文本 → 确认保存；
- 约束：必须提供「确认保存」与「重新生成」两个操作；校对为轻量操作（几十秒），不得设计成复杂审核流程。

### FR-4 模板保存与版本管理
- 每条模板记录：模板ID、版本号（V1.0、V1.1…）、生成时间、来源（图生/文生）、内容；
- 支持多版本共存；下游调用默认读取最新版本；
- 用户可查看历史版本、指定使用某一版本；
- 用户修改模板保存后，版本号自动 +0.1。

### FR-5 下游读取（手办 / VI 集成）
在手办 SOP、VI 表情包 SOP 的第一步（基准形象确认）增加逻辑：
- **已有模板**：读取选中的 IP 母版模板，将刚性锚点、柔性项规则、特例放行规则追加到本次生成约束中；柔性项按本次需求自由变更（如盲盒新服装、表情包新表情）；
- **无模板**：提示用户「可先生成 IP 模板（可选）」，或按原流程直接以参考图生成，不阻断原流程；
- 模板只读引用，不修改下游 SOP 本身流程。

### FR-6 冲突检测
当用户同时上传新参考图并选择读取旧模板时，检测两者刚性锚点是否明显冲突：
- 无冲突：正常执行；
- 有冲突：弹出提示，给出三个选项：①以模板为准（忽略新图差异特征）；②以新图为准并覆盖更新模板；③重新生成模板。

### FR-7 模板编辑
用户可随时手动编辑已保存模板（增删锚点、调整优先级、修改柔性项、填写特例放行规则），编辑后保存为新版本。

### 6.1 Markdown 格式（人读 / 直接追加进生图 Prompt）
```
【IP角色结构化模板】

▌刚性锚点（不可改动，必须保留，带优先级）
1.【最高优先级】标志性轮廓特征：<描述>
2.【最高优先级】脸型轮廓：<描述>
3.【次优先级】五官相对排布：<描述>
4.【次优先级】头身比：<描述>
▌柔性可变项（允许自由修改，用于系列变体）
1. 头发：发色、发型细节可更换

3. 服饰、配饰：可更换款式、颜色、花纹
```

## 7. 界面交互流程

### 7.1 独立模式（单独调用）
1. 入口页：选择生成方式【上传基准图】或【输入文字描述】；
2. 生成中：展示 AI 解析/结构化过程（进度态）；
3. 校对页：展示模板文本，可编辑；按钮【确认保存】【重新生成】；
4. 保存成功：展示模板卡片（版本号、时间、摘要），按钮【复制模板】【去跑手办/VI】。

### 7.2 内嵌模式（手办 / VI 流程内）
在「上传参考图」步骤追加可选按钮：
> 【可选：基于当前图片生成 IP 结构化模板】
- 点击 → 走 FR-1 → FR-3 校对 → 保存 → 自动应用为本次生成约束；
- 不点击 → 原流程不变。

### 7.3 下游读取交互（现网）

- **手办** `/ecom/hand-craft`、**品牌 VI** `/brand/vi` 参考区：**「从母版库导入」**（`IpMasterPickDialog`），选择母版库条目与版本；载入基准图并在生图 Prompt 追加 `buildIpMasterConstraintBlock`。
- **母版库 Tab**：`/library?tab=ip-master-library`（保存时须 **基准图 + 结构化模板** 齐备）。
- **FR-6 冲突三选一弹窗**：**尚未实现**（首版仅提醒；冲突时请手动选择以母版或新参考图为准）。

## 8. 非功能需求

| 类别 | 要求 |
|---|---|
| 轻量性 | 不强制生成模板；全部功能为可选分支，默认零额外操作 |
| 兼容性 | 原有「直接上传参考图跑图」流程完整保留，不受影响 |
| 通用性 | 模板格式同时支持图生与文生，产物完全一致 |
| 扩展性 | 模板可被任意下游流程读取；新增下游模块无需改模板结构 |
| 可迭代 | 版本管理支持无限次迭代，不产生混乱 |

## 9. 验收标准

| # | 验收项 | 通过标准 |
|---|---|---|
| 1 | 图生模板 | 上传基准图 → 输出标准格式模板，含刚性锚点（带优先级）与柔性项 |
| 2 | 文生模板 | 输入文字 → 输出同格式模板；缺失信息标「待补充」不编造 |
| 3 | 快速校对 | 生成后可编辑文本并保存；可重新生成 |
| 4 | 版本管理 | 修改保存后版本号递增；可查看/选择历史版本 |
| 5 | 下游读取 | 手办/VI 第一步可读取模板并把约束追加进 Prompt |
| 6 | 兼容旧流程 | 不生成模板时，手办/VI 全流程与改造前一致 |
| 7 | 冲突检测 | 新旧图与模板冲突时弹出三选一，不静默覆盖 |
| 8 | 模板 Prompt 追加 | 生成结果中，刚性锚点描述完整出现在提示词中，柔性项可被本次需求覆盖 |
