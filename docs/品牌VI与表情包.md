# 品牌 IP VI 与表情包自动生成 Skill

## Skill 名称：`brand-ip-vi-sticker-generator`

## Skill 定位

本 Skill 用于帮助用户从一个核心角色形象或品牌概念出发，自动完成一套完整的品牌 IP 视觉系统，包括：

- IP 基准形象
- 三视图规范
- 表情包系统
- Logo / 头像识别符号
- 文创周边设计
- 场景海报延展
- 品牌色与视觉规范建议

最终目标不是生成单张图，而是生成一套**可连续交付、可用于品牌传播、社媒发布、周边开发和表情包商用**的完整 IP VI 方案。

---

# 一、Skill 触发条件

## 1. 触发场景

当用户出现以下需求时，启动本 Skill：

- “帮我做一个品牌 IP”
- “基于这个人物生成表情包 / VI / 周边”
- “从一个角色生成三视图、Logo、海报、文创”
- “做一套品牌 IP 视觉系统”
- “做一套可商用的表情包”
- “把我的角色做成盲盒风 / 潮玩风 / IP 形象”

## 2. 必要输入

用户至少需要提供以下一种输入：

### A. 图片输入

- 人物形象图
- 手绘线稿
- IP 立绘
- 头像形象
- 品牌吉祥物

### B. 文字输入

- 品牌名称
- 角色性别 / 年龄气质
- 行业或用途
- 喜欢的风格
- 主色偏好
- 是否用于表情包、周边、Logo、海报

## 3. 输入不足时的追问规则

如果用户只说 “帮我做一套 IP VI”，但没有上传图片，也没有详细描述，必须按以下顺序追问，不允许直接乱生成。

### 追问话术

> 
> 为了生成完整的品牌 IP VI 和表情包，请先补充两项信息：
> 
> 
> 1. 你是否有参考图？比如人物形象、线稿、头像、Logo 草图或喜欢的风格图。
> 2. 品牌名称、角色气质、主色偏好是什么？
> 例如：AI 科技博主、Q 版、黑白 + 绿色、科技感、适合表情包和社媒头像。

# 二、核心执行原则

## 1. 先锁定基准形象，再做延展

本 Skill 的第一原则是：

> 
> 先确定唯一基准 IP 形象，后续所有物料都必须围绕这个基准延展，不允许每次重新设计角色。

基准形象一旦确认，后续必须保持：

- 脸型
- 五官比例
- 发型
- 配饰
- 服装特征
- 身体比例
- 主色体系
- 整体画风

## 2. 用户全程确认制

采用**分步确认机制**，每一步都先给用户明确选项，确认后再继续生成。
不允许一次性直接生成全部复杂物料。

## 3. 输出不是单一图，而是模块化方案

每个阶段都要形成独立模块：

- 基准形象模块
- 三视图模块
- 表情动作模块
- Logo / 头像模块
- 文创周边模块
- 海报场景模块
- 品牌规范模块

## 4. 风格统一原则

默认风格为：

- Q 版 IP
- 潮玩 / 盲盒感
- 干净矢量或 3D 质感
- 圆润、亲和、高识别度
- 适合社媒传播和周边开发

如果用户有明确风格，则切换为用户指定风格，例如：

- 国潮
- 赛博朋克
- 极简扁平
- 手绘治愈
- 复古卡通
- 商务科技
- 可爱萌系

# 三、完整执行流程

## 阶段 0：输入解析与方案建议

### 目标

先判断用户输入属于哪一类，再决定后续生成路径。

### 判断逻辑

表格

| 用户输入 | 执行策略 |
| --- | --- |
| 只有文字描述，没有图片 | 先生成 1 个基准 IP 形象方向，确认后再延展 |
| 有一张人物图 / 线稿 / 头像 | 以该图为唯一基准，先做基准形象规范化，再延展 |
| 已有 Logo 或品牌色 | 将 Logo 和品牌色纳入 VI 系统，角色视觉需与品牌统一 |
| 明确只要表情包 | 仍先建立基准角色，再批量生成表情 |
| 明确只要 Logo | 从角色头部提炼识别符号，不做全系列盲盒式展开 |
| 明确要全案 | 启动完整 10 阶段流程 |

### 输出内容

向用户说明：

> 
> 我将基于你的角色 / 品牌概念，按 “基准形象 → 三视图 → 表情包 → Logo → 文创 → 海报 → VI 规范” 的流程生成完整 IP VI 系统。每一步确认后再继续，确保角色造型和品牌风格保持一致。

---

# 阶段 1：建立唯一基准 IP 形象

## 目标

生成全系列唯一基准图，作为后续所有延展的视觉锚点。

## 输出内容

- 1 张标准 IP 基准形象图
- 标准站姿
- 正面为主
- 清晰展示发型、五官、服装、配饰、身体比例
- 干净背景，便于后续延展

## 默认生成 Prompt

```
基于用户提供的角色形象/线稿/品牌概念，生成唯一基准IP主形象。Q版潮玩风格，圆润可爱，高识别度，正面标准站姿，完整展示角色头部、发型、五官、服装、配饰、身体比例。保持用户原始角色的核心特征不变，干净背景，柔和光影，精致细节，适合后续生成三视图、表情包、Logo、文创周边和场景海报。
```

## 如果用户没有参考图，使用文字版 Prompt

```
生成一个原创品牌IP基准形象，角色类型为AI科技博主，Q版潮玩风格，正面标准站姿，年轻自信，科技感穿搭，黑色高领内搭，黑色纹理外套，耳钉配饰，发型有辨识度，表情亲和，整体圆润可爱，高饱和但干净，白色背景，适合后续生成表情包、Logo、三视图、文创和海报。
```

## 交付后话术

> 
> 这张图是全系列唯一基准形象。后续所有三视图、表情、Logo、文创和海报都将锁定这个角色特征，不再重新设计脸型、发型、配饰和比例。确认后进入下一阶段。

---

# 阶段 2：生成三视图规范

## 目标

让角色具备可复用、可建模、可周边化的结构规范。

## 输出内容

一张横向三视图图：

- 正面
- 侧面
- 背面
- 同一角色、同一比例、同一服装、同一配饰
- 白色背景
- 清晰标注视图名称

## Prompt

```
基于已确认的唯一基准IP形象，生成角色三视图规范图。正面、侧面、背面三个视图横向排列，保持同一角色的脸型、五官比例、发型、服装、配饰、身体比例、材质和色彩完全一致。Q版潮玩风格，白色背景，边缘整洁，结构清晰，适合后续建模、周边开发和品牌规范使用。画面文字标注：“正面”“侧面”“背面”。
```

## 交付后话术

> 
> 三视图已完成，角色结构已锁定。后续表情包和文创设计将严格沿用这套比例与造型。

---

# 阶段 3：生成基础表情与动作库

## 目标

先建立核心表情库，避免后续表情包随意变形。

## 输出内容

### 3.1 基础表情 4 款

- 开心
- 委屈
- 惊讶
- 慵懒

### 3.2 基础动作 5 款

- 讲解手势
- 比心
- 害羞捂脸
- 加油
- 发呆

## Prompt 模板

```
基于唯一基准IP形象，生成一个可爱表情图。严格保持角色的脸型、五官比例、发型、配饰、服装和整体画风一致。只改变表情和手势，不改变角色本体。白色背景，Q版潮玩风格，干净清晰，适合作为社媒表情包。
```

不同表情只需替换：

- “开心微笑，双手抬起讲解”
- “委屈托脸，眼神可怜”
- “惊讶睁眼，双手抬起”
- “慵懒发呆，半眯眼”
- “比心，亲和可爱”

## 交付后话术

> 
> 基础表情和动作库已完成。这里是后续九宫格表情包的核心素材，确认后可继续扩展完整表情包系统。

# 阶段 5：生成品牌 Logo / 头像识别符号

## 目标

从 IP 中提炼高识别度 Logo，而不是把角色图直接当 Logo。

## 输出内容

- 1 个品牌 Logo 方案
- 以角色头部为核心识别符号
- 结合品牌名称
- 简洁、扁平、适合头像使用
- 黑白 + 1 种点缀色，或贴合品牌调性配色

## Prompt

```
基于唯一基准IP形象的头部特征，设计品牌Logo。品牌名称为“吴越AI”。保留角色发型、脸部轮廓、配饰和核心气质，采用扁平化插画风，图形简洁，高识别度，适合作为社交媒体头像。文字“吴越AI”与角色头部视觉协调，整体干净，白色背景，色彩简洁。
```

## 交付后话术

> 
> Logo 已从角色头部提炼完成。后续建议在矢量软件中进一步规范文字和图形比例，用于头像、水印和品牌识别。

# 四、Skill 交互流程（适合可视化界面开发）

以下部分非常关键，因为你后面要做可视化界面，所以必须把交互步骤固定下来。

## 界面建议流程

### Step 1：用户输入

用户可以选择两种输入方式：

#### 方式 A：上传图片

- 人物图
- 线稿
- 头像
- Logo 草图

#### 方式 B：文字生成

- 品牌名称
- 角色描述
- 风格选择
- 主色选择

---

### Step 2：选择生成模式

界面给用户 5 个模式：

表格

| 模式 | 生成内容 |
| --- | --- |
| 1. 基础 IP 方案 | 基准形象 + 三视图 + 表情包 |
| 2. 表情包专项 | 九宫格表情包 + 单表情图 |
| 3. VI 专项 | Logo + 色卡 + 规范页 + 头像 |
| 4. 文创专项 | 周边样机 + 场景海报 |
| 5. 完整全案 | 基准形象 → 三视图 → 表情 → Logo → 文创 → 海报 → VI 规范 |

---

### Step 3：风格参数选择

建议界面提供以下可选参数：

表格

# 七、Skill 错误处理规则

## 1. 角色不一致问题

任何后续生成都必须检查：

- 脸型是否变化
- 发型是否变化
- 配饰是否变化
- 服装是否变化
- 比例是否变化
- 主色是否漂移

如果用户说 “不像同一个角色”，立即回到基准形象，不允许继续延展。

## 2. Logo 太复杂问题

Logo 必须简化，禁止把完整角色直接当 Logo。
Logo 建议只保留：

- 头部轮廓
- 发型符号
- 标志性配饰
- 品牌文字

## 3. 表情包变形问题

表情包只能改变：

- 表情
- 手势
- 动作

不能改变：

- 角色身份
- 头身比例
- 服装结构
- 主色体系

## 4. 周边风格混乱问题

所有周边必须统一：

- 同一角色
- 同一配色
- 同一画风
- 同一展示背景

## 5. 异常处理规则（后端逻辑）

1. 角色形象崩坏：用户反馈角色前后不一致 → 停止当前流程，回到基准图，基于基准图重新生成本模块，**不改动基准形象**；
2. 用户增减物料：用户要求增加 / 删减周边、减少表情数量，仅修改当前模块内容，基准 IP 保持锁定；
3. 输入缺失：用户只说 “做一套 IP VI”，没有图片 / 文字描述，自动弹出表单，引导补充品牌名称、角色描述、风格；
4. 风格切换：中途更换风格，**仅重新生成基准形象**，确认后再继续后续模块。
