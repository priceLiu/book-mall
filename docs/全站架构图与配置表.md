## 3. 身份与 Gateway 密钥（重要）

### 3.1 结论（先读）

| 问题 | 答案 |
|------|------|
| Canvas / Story / Tool / Prompt 各有一套 sk-gw 吗？ | **否**。全站共用 **Book 用户关联的那一把** `sk-gw`。 |
| Gateway 控制台为何只看到一条「Canvas Pilot」？ | 已统一为 **Platform Admin**（全站管理员密钥）；Book 子站应关联 **Personal** 个人密钥。管理员可同时持有两把。 |
| 各子站如何调用 AI？ | 浏览器 **不持 sk-gw**；持 `tools_token` → 调 Book `/api/sso/tools/gateway/*` → Book 用 `User.gatewayApiKeyId` 解析 sk-gw → 转发 Gateway。 |
| sk-gw 是给谁用的？ | ① Book 个人中心「关联」验证；② 外部直接调 Gateway `/api/v1`（`Authorization: Bearer sk-gw-...`）。子站 UI **不需要**也不应各自申请 Key。 |

### 3.2 用户生命周期

```mermaid
sequenceDiagram
  participant U as 用户
  participant B as book-mall
  participant G as gateway-web
  participant App as canvas/story/tool/prompt

  U->>B: 注册 Book
  B->>B: 创建 User + Wallet
  B->>B: syncGatewayUserFromBookUser（同邮箱 GatewayUser）

  U->>B: 个人中心「用 Book 账号打开 Gateway」
  B->>G: SSO issue → exchange
  U->>G: 绑定厂商凭证（KIE/百炼/DeepSeek…）
  U->>G: API 密钥 → 创建 sk-gw（Personal 供 Book 关联；Admin 另可建 Platform Admin）

  U->>B: 个人中心粘贴 sk-gw 关联（一次）
  B->>B: User.gatewayApiKeyId = 该 Key 的 ID

  U->>App: SSO 进入子站
  App->>B: /api/sso/tools/gateway/chat（tools_token）
  B->>B: resolveGatewayAuthForBookUser(userId)
  B->>G: 用关联的 sk-gw 转发
  G->>G: 用厂商凭证调云 API
```

### 3.3 两类「密钥」

| 类型 | 存在哪 | 用途 |
|------|--------|------|
| **厂商 API Key** | Gateway → 模型管理 / 厂商凭证 | DeepSeek、百炼、KIE 等；**只在 Gateway 维护** |
| **Gateway API Key (`sk-gw-...`)** | Gateway → API 密钥；Book 只存 **关联 ID** | 标识「哪个 Gateway 用户 + 绑定了哪些厂商凭证」；Book/子站代理 AI 时用 |

### 3.4 数据模型（简化）

```text
Book User (1) ──bookUserId──► GatewayUser (1)
Book User.gatewayApiKeyId ──► GatewayApiKey (当前关联 1 把，可更换)
GatewayUser ──► 多条 GatewayApiKey（scope: PLATFORM 管理员 / PERSONAL 个人；Book 关联 PERSONAL）
GatewayUser ──► 多条 GatewayCredential（厂商 Key）
GatewayApiKey ──bindings──► GatewayCredential
```

代码入口：`book-mall/lib/gateway/book-gateway-link.ts`（注释：**Canvas / Story / 工具站共用**）。

子站调用链：

- Canvas：`lib/canvas/canvas-gateway-client.ts` → `gateway-v1-http-client` → Book `/api/gw/v1/*`
- Story：`lib/story/story-gateway-client.ts` → 同上
- Tool / 电商：`tool-gateway-client` / `ecom-tool-gateway-client` → 同上
- Prompt：`/api/sso/tools/gateway/chat` → 同上

### 3.6 厂商零旁路（Gateway API 边界）

| 层级 | 允许做什么 |
|------|------------|
| **业务层**（`canvas-gateway-client`、`story-gateway-client`、`tool-gateway-client`、`ecom-tool-gateway-client`、`poll-service.runGatewayPollWorker`） | 只调 `lib/gateway/gateway-v1-http-client.ts`（`Gateway-Internal` + `apiKeyId`） |
| **Gateway API**（`book-mall/app/api/gw/v1/*`） | 唯一可解密厂商凭证、直连 KIE / DashScope / 百炼 / 火山 / 混元 HTTP |
| **gateway-web :3005** | 控制台 UI + 反向代理；**不**承载业务侧厂商 HTTP |

内部鉴权：`Authorization: Gateway-Internal {GATEWAY_INTERNAL_INVOKE_SECRET}:{apiKeyId}`（密钥见 `GATEWAY_INTERNAL_INVOKE_SECRET`，可回退 `GATEWAY_SSO_SERVER_SECRET`）。

异步轮询：`scripts/gateway-poll-loop.ts` / 生产 SCF 均经 `runGatewayPollWorker` → `gatewayV1RecordInfo`，不再业务层直连 `kie-client` / `dashscope-client`。

### 3.5 控制台里「只有一条 Key」是否正常？

**正常**，若你只创建过一条。若创建多条，Gateway **API 密钥** 页会列出全部；Book 个人中心显示 **当前关联** 的那一条前缀与名称。

要换 Key：在 Gateway 新建 sk-gw → Book 个人中心重新粘贴关联。

### 5.1 book-mall · 支付（Checkout 中台）

**用户入口**：`/checkout/*`（会员 / BYOK / 积分包 / VIP 预充）  
**API**：`POST /api/payments/checkout` · 企业微信 `POST /api/payments/wechat/create-order` · 异步通知 `POST /api/payments/wechat/notify`  
**运营**：Book **`/admin/payments`**（6 位备注码检索、待核对、确认到账）· finance-web **`/admin/reconciliation`** 支付明细

**渠道选择**（创建 Checkout 时自动判定，见 `app/api/payments/checkout/route.ts`）：

| 渠道 | 条件 | 用户侧体验 |
|------|------|------------|
| **`WECHAT_ENTERPRISE`** | `WECHAT_PAY_*` 配齐且 `isWechatPayConfigured()` 为 true | Native 扫码；**以 notify 验签为准**自动到账 |
| **`WECHAT_PERSONAL`** | 未配企业微信支付 | 静态个人收款码 + **6 位转账备注码**；点「我已完成支付」→ **待管理员核对**，不自动入账 |
| **`MOCK`** | 开发 / `ALLOW_MOCK_PAYMENT=true` | 模拟收银；**生产禁止**开启 `ALLOW_MOCK_PAYMENT` |

**企业微信支付 `WECHAT_PAY_*`**

| 变量 | 说明 |
|------|------|
| `WECHAT_PAY_MCHID` | 商户号 |
| `WECHAT_PAY_MCH_NAME` | 商户展示名（可选） |
| `WECHAT_PAY_APP_ID` | 微信 AppID |
| `WECHAT_PAY_API_V3_KEY` | APIv3 密钥 |
| `WECHAT_PAY_SERIAL_NO` | 商户 API 证书序列号 |
| `WECHAT_PAY_NOTIFY_URL` | 异步通知 URL，须与商户平台一致，如 `https://book.ai-code8.com/api/payments/wechat/notify` |
| `WECHAT_PAY_PRIVATE_KEY_B64` | **推荐**（CloudBase 单行）：`cd book-mall && pnpm wechat-pay:cloudbase-env` |
| `WECHAT_PAY_PRIVATE_KEY` | 商户私钥 PEM 原文（换行写 `\n`） |
| `WECHAT_PAY_KEY_PATH` | 私钥文件路径，默认 `certs/apiclient_key.pem`（entrypoint 可从 env 物化） |
| `WECHAT_PAY_PUB_KEY_PATH` | 微信支付公钥，默认 `certs/wechat_pay_pub_key.pem` |
| `WECHAT_PAY_PUBLIC_KEY` / `WECHAT_PAY_PUBLIC_KEY_B64` | 可选：公钥 inline，优先于文件 |

### 5.2 book-mall · 短信验证码与图形验证码

**能力**：手机号注册 / 验证码登录 / 绑手机 / 重置密码 / 团队邀请短信；发码前须通过 **加减法图形验证码**（`MathCaptcha`，无独立 env，令牌由 `NEXTAUTH_SECRET` HMAC 签名，5 分钟有效）。

**短信 Provider**

| 变量 | 说明 |
|------|------|
| `SMS_PROVIDER` | `mock`（默认，写库校验）或 `tencent`（腾讯云 SMS） |
| `TENCENT_SMS_SECRET_ID` / `TENCENT_SMS_SECRET_KEY` | 腾讯云 API 密钥 |
| `TENCENT_SMS_REGION` | 默认 `ap-guangzhou` |
| `TENCENT_SMS_SDK_APP_ID` | 短信应用 SdkAppId |
| `TENCENT_SMS_SIGN_NAME` | 已审核通过的签名文字 |
| `TENCENT_SMS_TEMPLATE_REGISTER` | 注册 / 登录 / 重置密码 **共用**（模板变量 `{1}` = 6 位验证码） |
| `TENCENT_SMS_TEMPLATE_BIND` | 绑定手机 |
| `TENCENT_SMS_TEMPLATE_TEAM_INVITE` | 团队邀请（`{1}` 验证码，`{2}` 团队名，`{3}` 邀请链接） |
| `SMS_ALLOW_BYPASS_CODE` | 未显式设为 **`0`** 时允许 **8 位临时 bypass**（6 字母 + 2 数字，顺序不限）；短信正式开通后生产 **必须 `SMS_ALLOW_BYPASS_CODE=0`** |

**阶段建议**（见 `deploy/tencent/book-mall.env.example`）：

| 阶段 | 配置 |
|------|------|
| A · 短信未开通 | `SMS_PROVIDER=mock`，bypass 默认开启，可先上生产联调 |
| B · 短信已开通 | `SMS_PROVIDER=tencent` + 填齐 `TENCENT_SMS_*` + **`SMS_ALLOW_BYPASS_CODE=0`** |

Mock 号段：`13800000001`–`13800000009` 固定验证码 **`888888`**（仅 dev/mock）。

权威：`docs/手机验证码 todo.md` · `book-mall/doc/product/16-phone-auth-and-sms.md`
