二、第一份Prompt：视频拉片解析Prompt（输出标准化拉片JSON）
 
直接整段发给大模型，强制只返回JSON，禁止任何前置后语、解释文字、markdown
 
plaintext
  
你是资深影视工业化拉片分析师，对我上传的这段视频做逐镜全维度专业拉片。
硬性输出约束，必须严格遵守，违反即视为错误：
1. 最终输出内容只能返回一段完整、合法、可直接JSON.parse()解析的JSON字符串。不能输出任何额外文字、开场白、说明、注释、markdown格式、表格。除JSON以外什么都不要写。

三、第二份Prompt：拉片JSON + 新角色 → 成片渲染脚本JSON Prompt
 
用户先拿到上面拉片JSON，上传角色素材/人设描述，调用这个Prompt，输出替换角色后的成片分镜JSON，同时增加顶层 renderGlobalConfig 渲染全局配置
 
plaintext
  
你将接收一段完整的标准化拉片JSON以及新角色人设/角色图像描述。
硬性输出约束，必须严格遵守，违反即视为错误：
1. 最终输出内容只能返回一段完整、合法、可直接JSON.parse()解析的JSON字符串。不能输出任何额外文字、开场白、说明、注释、markdown格式、表格。除JSON以外什么都不要写。
2. 继承原有拉片JSON内全部镜头时序、镜头数量、单镜头时长、转场、景别、机位、运镜轨迹、焦距透视、构图、场景环境、布光光影、色调影调、音频信息、叙事功能、节奏权重全部要素；仅将原视频内原有角色统一替换为接下来给到的新角色设定。
3. 约束规则：镜头数量、镜头顺序、单镜头时长、转场方式完全不变，不新增、不删减镜头；新角色每镜内站位、移动轨迹、肢体动作、视线方向严格复刻原角色动作逻辑；前景中后景分层、道具、场景环境、光影布光全部原样保留，只替换人物主体；音频信息完整继承原拉片内容；aiVisualPrompt字段全部重写，完整嵌入新角色形象特征，产出可以直接给到视频生成API渲染单镜头的视觉prompt。
4. JSON顶层新增renderGlobalConfig字段，用来放整条视频全局渲染参数；meta、shots内部字段名、结构与原拉片JSON完全保持一致，所有字段一个不能少，字段名称大小写拼写完全不能改动，无内容填"无"。

四、产品侧额外兜底策略（后端做，Prompt里不用写）
 
1. 大模型返回结果先做正则清洗：截取最外层 { ... } ，剔除前后多余文字，再执行JSON.parse()；
2. 使用上面这份Schema做字段强校验，缺失字段、字段类型不对直接打回，自动重跑一次请求；
3. 内部维护一份字段枚举池（景别枚举、转场枚举等），解析后做二次标准化清洗，进一步稳定输出。
