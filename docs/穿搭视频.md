一、功能整体概述
1.1 业务背景
平台已具备成熟模特素材库、服装商品库，原有一键式AI视频生成属于黑盒全自动模式：用户提交素材后无任何干预权限，成片不可控、废片率高、无法自定义镜头节奏，无法满足精细化商业穿搭内容生产需求。
本次升级 【可视化分镜可控版穿搭视频动作迁移功能】：基于参考视频真实镜头结构拆解分镜、生成分镜预览图，开放用户分镜级编辑干预权限，用户确认镜头后再批量生成视频片段，最终无缝合并成片。兼顾AI自动化效率与人工精细化可控度，属于商业级成熟工作流。
1.2 核心设计原则（硬性技术规范）
- 禁止文本驱动动作：动作、镜头、时序全部由视频解析结构化数据控制，不由Prompt文字描述控制
- 全链路JSON结构化：所有AI入参、分镜数据、AI返回结果100%标准化JSON，无自由文本
- 三层条件驱动生成：骨骼动作时序 + 模特身份特征 + 服装版型特征，Prompt仅做画质/风格/兜底约束
- 可干预、可编辑、可回溯：打破黑盒生成，分镜可视化、支持单镜重绘、删除、调整、重生成
- 前后端解耦：AI只输出标准JSON结构，前端根据JSON字段解析渲染分镜、参数、视频信息
1.3 能力边界（明确可做/不可做）
✅ 可实现：参考视频真实镜头拆解、结构化分镜提取、分镜预览图生成、用户分镜编辑、单镜重生成、分段视频合成、动作复刻、模特服装锁定
❌ 不实现：不通过大模型虚构文字分镜脚本（精度过低、废弃方案），所有分镜源自原视频真实时序结构

二、全新升级用户操作流程（可视化可控版）
新增分镜预览编辑环节，用户拥有完整干预权，不再是无脑一键生成：
1. 步骤1：进入【穿搭视频迁移】功能模块
2. 步骤2：选择模特 —— 从平台模特库选择/上传模特图
3. 步骤3：选择服装 —— 从平台服装库选择对应穿搭服装
4. 步骤4：上传参考视频 —— 上传9:16竖屏爆款穿搭参考视频
5. 步骤5：后端自动解析拆镜 —— 拆解N段真实物理分镜、输出结构化分镜JSON + 每段分镜预览图
6. 步骤6：用户可视化编辑干预（核心新增） —— 查看所有分镜、删除劣质镜头、单独重生成某一分镜、调整镜头顺序
7. 步骤7：确认分镜队列，提交批量生成视频片段
8. 步骤8：后端无缝合并所有片段，输出完整10-15秒成片
9. 步骤9：前端解析JSON返回结果，展示成片、参数、状态

三、全新升级核心技术链路（可控制、可编辑版）
用户素材输入 → 参考视频真实镜头拆解（非文本AI脑补） → 结构化分镜时序数据 + 分镜预览图 → 用户编辑确认 → 逐镜骨骼迁移生成视频片段 → 帧对齐合并 → 成片输出
1. 视频分镜解析模块（核心新增）：对参考视频做镜头检测、场景切割、动作分段，拆分出真实物理分镜（每段2-4s）；逐段提取骨骼关键点、机位、动作、光影参数；输出分镜预览关键帧图片。
2. 分镜结构化存储模块：每一段镜头独立JSON对象，支持前端单独渲染、单独操作、单独重跑任务。
3. 特征绑定模块：锁定模特身份特征、锁定服装版型/色彩/面料特征，全部分镜统一特征参数，杜绝前后不一致。
4. AI生成模块（千万3.8 Max）：支持全局批量生成与单分镜单独重生成，基于每段镜头骨骼时序精准迁移。
5. 视频合并后处理模块：自动对齐所有分段首尾帧、消除拼接断层、全局统一光影色调、防抖降噪，合成完整成片。
6. 结果封装模块：强制输出分镜级+成片级双层标准JSON，前端完全可视化渲染。

## 一、千万 3.8 Max 分镜解析 System Prompt【最终定稿，复制直接用】

```

你是视频分镜解析助手，依据视频分段时间戳与对应关键帧截图，输出标准化JSON分镜数组。

## 输入
1. 每段分镜：镜号、开始时间、结束时间、时长；
2. 当前镜头对应的关键帧截图。

## 输出字段严格定义
每一条分镜对象字段固定：
{
    "scene_id": "字符串镜号，s1、s2、s3",
    "start_time": 数字，片段开始秒数,
    "end_time": 数字，片段结束秒数,
    "duration": 数字，片段时长秒数,
    "camera_desc": "运镜完整中文描述，识别不到写：无法识别运镜",
    "action_desc": "模特动作描述，聚焦服装展示，完整通顺句子，识别不到写：无法识别模特动作",
    "light_desc": "光影完整中文描述，光源、色温、光线软硬；识别不到写：无法识别光影信息",
    "scene_desc": "场景完整中文描述，空间、物体、色调；识别不到写：无法识别场景信息",
    "parse_incomplete": false
}

## 强制硬性规则
1. 所有文本字段必须输出**完整通顺句子，严禁半截短语、截断、不完整结尾**。画面信息不足，直接填写“无法识别xxx”，禁止输出残缺文字。
2. 只输出纯JSON数组，不要markdown表格，不要解释、不要额外说明文字。
3. 只描述截图可见内容，不脑补虚构画面；优先记录衣服版型、裙摆、腰带等穿搭相关信息。
4. parse_incomplete 默认 false；只有画面模糊严重，完全无法提取有效信息，设置为 true。
5. camera_desc、action_desc 仅用于UI展示归档，不需要适配AI绘图提示词格式。

## 业务提醒
输出的 light_desc、scene_desc 后续会被前端预填充到生成提示词输入框供用户人工确认修改，所以输出语句通顺可读即可，不要堆砌杂乱关键词。
```

## 三、后端校验 & 容错逻辑（解决截断残缺，最终版）

拿到大模型返回 JSON 后遍历每一条分镜：

1. 残缺判定条件（满足任意一条视为残缺）
   - 字段结尾语义未收尾，半截短语；
   - 字符串无完整主谓短句；
   - 不等于 “无法识别 xxx”，同时字符过短。
2. 处理流程
   - 检测到残缺 → 设置 `parse_incomplete=true`，**触发最多 2 次重试调用大模型重新解析该片段**；
   - 重试 2 次依旧残缺：`light_desc="【AI识别不足，请手动编辑】"`，`scene_desc="【AI识别不足，请手动编辑】"`；
3. ❌ 后端绝不自己做语义补全，不拼接字符串修复句子。

# 通义 qwen‑image‑edit 参数 & 提示词（可直接复制使用）

> 
> 入参说明

- `image_ref`：VTON 输出的模特穿好衣服的全身人像图（人物参考图）
- `style_ref`：用户上传的场景参考图（场景参考）
- `image_ref_strength`：**0.72‑0.78**
  - 太高 (>0.82)：人物完全不变，但不会适配场景光影，像抠图贴背景
  - 太低 (<0.68)：人脸、衣服容易被篡改，后续动作迁移人脸漂移

## 正向提示词

```
商业电商人像摄影，9:16竖版，高清8K，真实相机拍摄。
模特保持正面站立全身人像，严格保留原模特五官脸型、发型、服装款式、面料与印花细节，不要改变人物样貌。

```

## 负向提示词

```
人脸变形，五官错位，脸部扭曲，修改服装款式，服装印花丢失，肢体畸形，手部崩坏，身体扭转侧对镜头，背影，卡通，手绘，绘画，水印，文字，模糊，多余肢体。
```

# 完整业务伪代码逻辑

```
# 输入
person_vton_img = VTON(模特原图,服装图) #阿里aitryon‑plus输出，穿好衣服的全身模特
scene_ref_img = 用户上传的场景图

# 调用千问图像编辑
resp = qwen_image_edit(
    image_ref = person_vton_img,
    style_ref = scene_ref_img,
    image_ref_strength = 0.75,
    prompt = 上面正向提示词,
    negative_prompt = 上面负向提示词
)
static_final_img = resp.output_img_url
# static_final_img：正面站立，人脸服装正确，已经融合进新场景、光影对齐的静态图

# 送入Kling动作迁移
kling_params = {
    "image": static_final_img,
    "reference_video": clip_4s, #4秒切片，动作完全由视频接管
    "prompt": "9:16竖屏，电商穿搭短视频，高清真实，画面稳定流畅，保留人物样貌服装与场景氛围，动作跟随参考视频",
    "negative_prompt": "人脸闪烁漂移，肢体畸形，鬼手，画面抖动闪烁，模糊"
}
```

### 关键理解再次强调

1. qwen‑image‑edit 产出的是**一张正面站立的静态参考图**，它只负责告诉 Kling：这个人长什么样、穿什么衣服、在什么环境、什么光影基调。
2. **视频里面抬手、转身、走动全部由 reference_video 切片控制**，静态图的站立姿态会被视频动作覆盖，不用担心静态是站立，视频动不起来。
3. 即便静态图场景融合很好，Kling 生成视频做大动作时，背景依旧存在局部变形、4 秒切片之间轻微跳动的底层限制，产品 UI 要保留提示。

## UI 给用户的提示文案

> 
> 场景参考图：系统生成一张正面站立的模特静态参考图并融合到目标场景；视频的动作完全跟随参考视频；背景可以得到很强的参考，但无法做到 100% 完全锁定，片段间可能存在轻微跳动。
