## 4. 工单类型

业务日固定 **Asia/Shanghai（UTC+8）**。

### 4.1 `BATCH_EXPIRE` — 批次到期清扫

**来源**：`CreditLot` where `remainingCredits > 0` AND `expiresAt IS NOT NULL`

| 场景 | 条件 |
|---|---|
| 今日到期 | `date(expiresAt, CST) = 业务日` |
| 逾期 | `expiresAt < startOfDay(CST)` 且无 `DONE` 工单 |

**执行**：`expireDueLotsForAccount`（写 EXPIRE、批次归零）

覆盖：FREE 30 天、TOPUP 12 月、过期 SUBSCRIPTION 批次。

### 4.2 `SUBSCRIPTION_RESET` — 订阅 31 天刷新

**来源**：`CreditAccount` where `monthlyGrantCredits > 0` AND `currentPeriodEnd IS NOT NULL`

| 场景 | 条件 |
|---|---|
| 今日到期 | `date(currentPeriodEnd, CST) = 业务日` |
| 逾期 | `currentPeriodEnd < now` 且无本周期 `DONE` 工单 |

**执行**：`resetMonthlyCredits`（清上一周期订阅批次 + 发放新周期）

**合法跳过（记 `SKIPPED`）**：

- 团队 `Tenant.status != ACTIVE`
- 会员服务已过期（`membershipPaidUntil` / `Tenant.currentPeriodEnd`）
- VIP（`monthlyGrantCredits = 0` 且 `currentPeriodEnd = null`）

## 5. 工单状态机

```
PENDING ──执行──► RUNNING ──成功──► DONE
                      ├──失败──► FAILED
                      └──跳过──► SKIPPED

PENDING（dueDate < today）──► OVERDUE（自动升级，触发预警）
OVERDUE ──补跑成功──► DONE（isBackfill=true）
```

**唯一约束**：`(workType, accountId, pool, dueDate, periodKey)` — 同一账户同一周期只建一条。

## 6. 预警规则

| Code | 级别 | 条件 |
|---|---|---|
| `CRON_NOT_RUN` | CRITICAL | 今日 01:00 CST 后无 `DAILY_*` JobRun |
| `OVERDUE_ITEMS` | CRITICAL | `OVERDUE` 工单数 > 0 |
| `PARTIAL_RUN` | WARN | 最近 JobRun = `PARTIAL` |
| `UNDER_PROCESSED` | WARN | JobRun 成功但 `done < total` |
| `DRIFT_DETECTED` | WARN | 工单 DONE 但对账不一致 |
| `STALE_SUBSCRIPTION_LOTS` | WARN | SUBSCRIPTION 批次 `expiresAt < now` 且 remaining > 0 |

**展示位置**：

1. finance-web 顶栏预警条（admin layout）
2. 侧栏「积分清零运维」badge
3. `/admin/credit-expiry-ops` 概览区

## 7. API 契约

### 7.1 Cron / 管理员（book-mall）

鉴权：`x-vercel-cron:1` / `Bearer CREDITS_CRON_SECRET` / `?secret=` / ADMIN 登录

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/admin/credits/ops/generate-work-items` | 生成/更新工单（`?date=&includeOverdue=1`） |
| POST | `/api/admin/credits/ops/run-daily` | 执行（`?phase=expire\|reset\|all&dryRun=1&date=`） |
| POST | `/api/admin/credits/expire-sweep` | 兼容入口 → ops expire |
| POST | `/api/admin/credits/monthly-reset` | 兼容入口 → ops reset |

### 7.2 财务运维台（finance-web → book-mall）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/finance/admin/credit-expiry-ops/dashboard` | 概览统计 |
| GET | `/api/finance/admin/credit-expiry-ops/work-items` | 工单列表 |
| GET | `/api/finance/admin/credit-expiry-ops/job-runs` | 执行历史 |
| GET | `/api/finance/admin/credit-expiry-ops/alerts` | 预警列表 |
| POST | `/api/finance/admin/credit-expiry-ops/run` | 手动执行/补跑 |

## 10. 数据模型

### `CreditOpsJobRun`

批量执行记录：`jobType` · `scheduledDate` · `trigger` · `status` · `statsJson` · `startedAt` / `finishedAt`

### `CreditOpsWorkItem`

单账户工单：`workType` · `dueDate` · `accountId` · `ownerHint` · `expectedExpireCredits` · `status` · `processedAt` · `resultJson`

代码：`book-mall/lib/billing/credit-ops-service.ts` · `credit-ops-alerts.ts`

---

## 11. 对账校验

执行完成后校验：

1. `BATCH_EXPIRE`：目标批次 `remainingCredits = 0` 或 EXPIRE 流水金额一致
2. `SUBSCRIPTION_RESET`：存在 `monthly_grant` 流水；`currentPeriodEnd` 推进 31 天
3. 账户不变量：`sum(lot.remaining) == balance + reserved`（按池）

不一致 → 工单 `FAILED` 或预警 `DRIFT_DETECTED`。
