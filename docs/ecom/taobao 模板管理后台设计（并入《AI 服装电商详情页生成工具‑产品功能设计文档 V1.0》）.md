> **已并入 SSOT**：[`docs/ecom/详情页套图.md`](./详情页套图.md)。本文仅作历史底稿；后台现为「按平台复制种子 + 可增删大模块」。

> 定位：独立后台模块，用于**管理多套品类模板**，维护 12 个顶层模块、各模块内部子维度候选池；支持新增 / 复制 / 编辑 / 删除模板、增删改子维度，供前端生成详情页任务时调用。
> 底层约束：**12 个顶层 module_id 固定不可增删**，后台仅允许修改模板内每个模块的：`max_num`、`candidate_pool`子维度列表，不允许新增 / 删除顶层 12 个板块。

## 一、后台核心能力清单

1. 模板列表管理：查看全部系统预置模板 + 用户自定义模板
2. 模板新增：两种方式
   - 方式 A：空白新建（极少用，推荐复制）
   - 方式 B：**复制现有模板**（主推，复制一份已有模板，再修改内容，降低配置成本）
3. 模板编辑：
   - 修改模板基础信息：模板名称、所属品类、备注
   - 进入 12 大模块配置页：对每一个模块，修改`max_num`最大阈值、编辑`candidate_pool`子维度候选池（新增、删除、修改子维度文本、拖拽排序子维度顺序）
4. 模板启用 / 禁用：禁用后的模板，前端下拉选择框不再展示，不可用于生成任务
5. 模板删除：仅**用户自定义模板**可删除；系统预置模板禁止删除，仅支持查看，不可直接编辑（想要修改系统模板，必须先复制成自定义模板再修改）
6. 模板预览：在后台可预览当前这套模板的 12 模块、每个模块子维度清单，快速核对
7. 模板导入 / 导出：导出整套模板 JSON 备份；支持导入 JSON 文件新增模板（方便跨环境迁移模板配置）

> 
> 权限规则：
> 
> 
> - 系统预置模板：type=`system`，只读，不可编辑、不可删除，可复制
> - 用户自定义模板：type=`user`，完全可编辑、可删除、可复制、可启用禁用

## 二、后台页面结构

### 页面 1：模板列表页（首页）

字段列表展示：

表格

| 字段 | 说明 |
| --- | --- |
| 模板 ID | template_id，唯一标识，自动生成，不可修改 |
| 模板名称 | 例如：户外外套 / 羽绒服、商务正装衬衫 |
| 品类标签 | 服装品类：户外服饰 / 商务衬衫 / T 恤休闲等 |
| 模板类型 | 系统预置 / 用户自定义 |
| 状态 | 启用 / 禁用 |
| 创建时间 |  |
| 操作按钮 | 【复制模板】【编辑】【预览】【导出 JSON】【删除】（系统模板删除按钮灰化） |

顶部操作按钮：【新建空白模板】【导入模板 JSON】

### 页面 2：模板编辑页

分为两大标签页：

> 
> 标签 1：模板基础信息

- 模板名称
- 品类名称
- 备注（可选，记录用途，如 “男装商务衬衫，淘宝平台”）
- 模板状态：启用 / 禁用

> 
> 标签 2：12 模块配置（核心页面）
> 一次性加载固定 12 个顶层模块（module_id 固定，顺序固定，不能删减）
> 每一行对应 1 个顶层模块，展示：

1. 模块 ID（只读，例如 mod4_detail）
2. 模块名称（只读，例如细节特写模块）
3. 是否必选（只读，必选标记由系统固定，不能修改）
4. 最大生成数量 max_num：数字输入框
   - 校验：正整数；max_num ≥1
5. 子维度候选池【candidate_pool】编辑区域
   - 列表展示所有子维度条目
   - 单行条目：文本框 + 【上移】【下移】【删除】按钮
   - 按钮【+ 添加子维度】，新增一行空白文本用于录入新子维度
   - 支持拖拽排序子维度（影响前端下拉 / 勾选框展示顺序）

> 
> 保存校验规则（保存模板时自动校验）

1. 必选模块：max_num ≥ 1
2. candidate_pool 不能为空，至少包含 1 条子维度
3. candidate_pool 里面不能出现空字符串
4. 同一模块内子维度不允许完全重复文本

### 页面 3：模板预览页面

只读展示，结构化展示整套模板：
模板基础信息 + 12 模块列表，每个模块展示：模块名称、必选 / 可选、max_num、完整子维度清单。用于快速核对配置，不支持编辑。

## 三、后台数据结构（模板存储结构，和前端任务引擎共用同一套 JSON Schema）

> 
> 和之前文档的 template 结构完全保持一致，保证前后端同构，避免解析冲突

```
{
  "template_id": "outdoor_jacket_001",
  "template_name": "户外外套/羽绒服",
  "category": "户外服饰",
  "type": "system",
  "status": "enable",
  "remark": "5套竞品提取，男装户外羽绒服详情模板",
  "modules": [
    {
      "module_id": "mod1_banner",
      "module_name": "首屏主视觉海报",
      "required": true,
      "max_num": 1,
      "candidate_pool": [
        "首屏模特全身氛围感穿搭，产品主体突出，宽幅详情长图"
      ]
    }
    //剩余11个模块结构同上
  ]
}
```

新增字段用于后台管理：

- `status`：enable / disable
- `remark`：备注
- `create_time`：创建时间
- `create_user`：创建人 ID

## 四、后台操作业务流程

### 场景 1：复制系统预置模板，修改成自定义模板

1. 在模板列表，找到系统预置【户外外套 / 羽绒服模板】，点击【复制模板】
2. 系统生成一条全新 template_id，type 自动改为`user`
3. 进入编辑页，修改模板名称，例如「我的定制户外羽绒服模板」
4. 进入 12 模块配置，例如修改 mod4_detail 细节模块：
   - 修改 max_num 从 11 改为 9
   - 删除不需要的子维度（魔术贴）
   - 新增自定义子维度（充绒量切面特写）
   - 拖拽调整子维度展示顺序
5. 保存，校验通过后模板生效，前端生成页面下拉框可以选择该模板

### 场景 2：新建空白模板

1. 点击【新建空白模板】
2. 填写模板名称、品类
3. 依次对固定 12 个模块，逐个填写 max_num，录入子维度候选池

> 
> 不推荐，工作量大，优先复制模板方式

### 场景 3：导出 / 导入模板

1. 导出：点击导出 JSON，下载完整模板 JSON 文件，用于备份或者迁移到其他环境
2. 导入：上传 JSON 文件，系统校验 JSON 结构合法性；校验成功，新增一条用户自定义模板

## 五、权限与约束

1. **12 个顶层模块 module_id、模块名称、required 必选标记全部固定，后台不可修改**
> 
> 后台只能改每个模块内的 max_num、子维度候选池，不能增删顶层 12 板块。
2. 系统预置模板禁止编辑、删除；只能复制。
3. 子维度仅为**拍摄主体描述**，后台只保存文本；不存储完整 prompt。Prompt 是在前端提交任务时，送入大模型动态润色生成。
4. 模板删除：仅自定义模板允许删除；**模板一旦被详情任务引用（任务使用过这个模板），增加二次确认弹窗，防止误删正在使用的模板**。

## 六、后台操作校验提示文案

1. 子维度为空：`子维度文本不能为空，请输入内容或者删除该行`
2. 模块候选池为空：`该模块子维度列表不能为空，至少保留1条`
3. max_num 输入 0：`必选模块最大数量不能小于1`
4. 导入 JSON 结构异常：`JSON解析失败，模板结构不符合规范，请检查文件`
5. 删除被任务引用的模板：`该模板已经被历史生成任务引用，确认删除？删除后历史任务不受影响，但无法再新建任务选用该模板`

## 七、和详情生成主流程联动关系

1. 用户进入【详情生成页面】，下拉选择模板，前端请求后台接口，读取该模板完整 JSON
2. 前端渲染 12 个模块、每个模块 max_num、子维度候选池，给到用户勾选 / 随机抽样
3. 用户配置完成提交任务，把模板 ID、选中子维度列表传给大模型生成 prompt
4. 修改模板，**不会影响已经生成完成的历史任务**（历史任务会缓存当时选中的子维度快照，和模板解耦，模板后续修改不改动旧任务结果）

> 
> 重点：历史任务做快照机制，任务一旦创建，会保存一份当前选中子维度快照；后续模板修改，不会改变已经跑完的旧任务，避免结果变更。
