## 1. 产品决策

| 决策 | 内容 |
| --- | --- |
| 产线 | **全新入口**。不改「详情页套图」七维模板流程，也不走复刻 12 模块固定框架 |
| 合规 | 不保存、不返回、不出图使用竞品原图/原文；界面常驻合规提示 |
| 拆解 | 单次 Vision：结构范式 + 文案范式 + 视觉氛围，输出 `detail-page-suite-hit/v1` |
| 卡位 | `component_list` 数量不固定；支持增删、上下移动、改 `repeat_count`、重置为 AI 快照 |
| 融合 | 文本 LLM 按「爆款叙事 + 新品卖点」原创重写并写出生图 Prompt |
| 出图 | 复用套图出图；参考图仅 `product` / `model`，**不含**竞品长图 |
| 画布 | 模板 `canvas_width=750`；展示/出图比例沿用套图平台比例 |
| 计费 | `toolKey: ecom-toolkit__detail-page-suite-hit`，navKey 归入 **`e-commerce-toolkit`** |
| 落库 | 同表 `EcomDetailPageSuiteProject`，`module = detail-page-suite-hit` |

## 2. 用户流程

1. 上传竞品淘宝详情长截图（拆解必填）
2. 上传自有新品产品图、可选模特；填写新品卖点（**AI 识图卖点**为异步任务，`meta.hitVisionSellpoint.progress.percent` 持久化，前端 **800ms 轮询** `GET project` 更新进度条）
3. **拆解爆款范式** → 可编辑卡位列表（类型 / 排版 / 数量 / 顺序）
4. **生成原创文案与 Prompt**（未填卖点则拦截）
5. 下区格子编辑 **模块文案**（`slot_copy`）与 **出图提示词**（`positive_prompt`，默认不含画面文字）→ 可选「出图时渲染模块文案」→ 出图

## 3. LLM 围栏与 JSON

### 3.1 范式拆解

- 围栏：`` ```detail-page-suite-hit ``
- `schemaVersion`: **`detail-page-suite-hit/v1`**
- 持久化：`meta.hitTemplate`；首次成功另存 `meta.hitTemplateSnapshot`

组件枚举：`full_banner` / `main_product` / `feature_card` / `spec_table` / `detail_closeup` / `scene_image` / `contrast` / `after_sale` / `other`  
排版：`full_image` / `image_text_top_bottom` / `image_text_left_right` / `text_only` / `table`

禁止输出：竞品原文句子、像素坐标、原图 base64、可识别服饰花纹/logo。

**拆解必含（与 [爆款结构复制.md](./爆款结构复制.md) 增补一致）**

| 对象 | 字段 | 说明 |
| --- | --- | --- |
| `market_insight` | `hot_selling_dimensions` | 爆款卖点**维度**（方向标签，非原句） |
| | `user_pain_points` | 类目用户痛点 |
| | `narrative_sequence` | 叙事顺序 |
| | `copy_style` | 文案口吻 |
| | `module_copy_functions` | 各模块核心文案功能（抽象钩子，非原文） |
| `global_style` | 七维 | `scene_environment` / `light_style` / `color_tone` / `composition_style` / `picture_atmosphere` / `prop_style` / `clarity_texture` |

工作台「爆款洞察」「视觉场景氛围」面板可编辑；保存走 `POST .../hit/template`。持久化另写 `meta.hitMarketInsight`。

**服务端 JSON 交互（SSOT：`book-mall/lib/ecom/detail-page-suite-hit/hit-schemas.ts`）**

1. `extractFenceJson` 取围栏内 JSON  
2. `coerceHitTemplateRaw` 容错（类型别名、数字字符串、缺省插槽）  
3. `HitTemplateSchema`（zod）校验  
4. `normalizeHitTemplateDetailed` 产出 `schemaVersion=detail-page-suite-hit/v1`、`canvas_width=750`、稳定 `component_list[].id`，并按类型截断 `repeat_count`  
5. 截断/规范项写入 `meta.hitWarning`（前端黄条）；`POST .../hit/template` 保存编辑时同样走 normalize  

`repeat_count` 上限：`feature_card≤6`，`detail_closeup`/`scene_image≤8`，其它类型固定 `1`。

### 3.2 原创重写

- 围栏：`` ```detail-page-suite-hit-rewrite ``
- `schemaVersion`: **`detail-page-suite-hit-rewrite/v1`**
- 输入：`market_insight` + `global_style`（七维氛围）+ 用户新品卖点（优先）；输出按 `component_id` + `repeat_count` 分配 `slot_copy` / `positive_prompt`
- `positive_prompt`：画面与商品描述（默认**不含**详情页排版文案）；`slot_copy` 为模块文案，格子可编辑；出图时若勾选 `settings.hitIncludeSlotCopyOnImage` / 请求体 `includeSlotCopyOnImage`，服务端将文案追加进生图 prompt 并放宽负向里的「文字」项
- 服务端：`coerceHitRewriteRaw` → zod → `normalizeHitRewrite(raw, expected[])`；`expected` 来自当前 `hitTemplate.component_list` 的 `{ id, repeat_count }`，**条数必须与 repeat 一致**，缺组件或未知 id 直接报错（不静默丢字段）

## 4. API

前缀：`/api/sso/tools/ecom/detail-page-suite-hit/`

| 路径 | 作用 |
| --- | --- |
| `GET/POST projects` | 列表 / 创建 |
| `GET/PATCH/DELETE projects/:id` | 读写删 |
| `POST projects/:id/upload` | 竞品长图 / 新品 / 模特 |
| `POST projects/:id/vision/sellpoints` | 新品图识图卖点 |
| `POST projects/:id/hit/decompose` | 异步拆解 |
| `POST projects/:id/hit/template` | 保存卡位编辑或 `reset` |
| `POST projects/:id/hit/rewrite` | 原创文案 + Prompt |
| `POST projects/:id/images/generate` | 出图 |
