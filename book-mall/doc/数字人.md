项目功能设计文档：全自动数字人带货视频工厂
文档版本：V2.0
目标平台：云端全自动部署（Node.js + 阿里云生态）
核心目标：实现“数字人形象 + 口播音频 + 背景视频”三大仓库的资产管理与一键云端合成。

1. 项目背景与核心逻辑
本项目旨在解决批量制作带货口播视频的效率问题。用户无需学习剪辑软件，只需上传素材，系统即可在云端全自动生成成品视频。

核心玩法（搭积木模式）：

数字人库：上传照片，建立多个虚拟形象。

音频库：上传录音或使用 TTS 生成台词。

视频创作库：上传已拍好的产品背景视频。

一键合成：任意挑选上述三个资产，点击合成，云端自动输出成片。

2. 系统架构与技术栈选型
所有计算和渲染任务均在云端服务器完成，用户端仅需调用 API 或操作网页。

2.1 技术栈全景
后端语言：Node.js (v18+) + Express.js。

AI 数字人模型：阿里云 DashScope (百炼) - wan2.2-s2v（单图+音频驱动）。

AI 语音合成 (TTS)：阿里云 CosyVoice-v3-Flash（高保真、情感细腻）。

视频合成引擎：FFmpeg（安装在云服务器 Linux 环境中）。

对象存储：阿里云 OSS（用于存储所有图片、音频、视频资产及最终成片）。

数据库：SQLite (开发) / PostgreSQL (生产)（用于记录资产元数据）。

2.2 选型特殊说明
为什么只用阿里云 wan2.2-s2v？：本项目第一阶段优先保证接入稳定性和统一性。阿里云模型支持 720P 高清输出，且提供 100 秒免费额度。

为什么选 CosyVoice？：相比普通 TTS，CosyVoice-v3-Flash 支持通过自然语言控制情感（如“用兴奋的语气说”），音质更饱满，更适合带货场景。

MiniMax 方案定位：MiniMax 的 TTS 和数字人同样优秀，但考虑到统一鉴权和调用链路，本项目初期先不接入。文档末尾将预留 MiniMax 的扩展接口说明，待阿里云链路跑通后可无缝增加。

3. 核心数据实体设计（ER 图逻辑）
系统内部需维护以下 4 张核心数据表（AI 编程工具需据此构建 Model）：

3.1 数字人表 (DigitalHumans)
记录所有上传的照片形象。

字段名	类型	说明
id	String (UUID)	主键
name	String	用户自定义名称（如“知性姐姐”）
avatar_image_url	String	上传的原始照片 URL（存入 OSS）
status	Enum	active / inactive
created_at	DateTime	创建时间
3.2 音频表 (Audios)
记录所有口播声音文件（含 AI 生成和本地上传）。

字段名	类型	说明
id	String (UUID)	主键
name	String	音频名称
source_type	Enum	upload(本地上传) / tts(AI生成)
audio_url	String	音频文件 URL（MP3 格式，存 OSS）
duration	Float	时长（秒） 【关键限制：必须 < 20秒】
text_script	Text	台词文本（用于后期自动生成字幕）
created_at	DateTime	创建时间
3.3 视频创作库表 (VideoMaterials)
专门存放作为背景画面的视频成品。

字段名	类型	说明
id	String (UUID)	主键
name	String	视频名称（如“羽绒服展示”）
video_url	String	背景视频文件 URL（存 OSS）
duration	Float	背景视频时长（秒）
created_at	DateTime	创建时间
3.4 合成任务表 (ComposeTasks)
核心流水线记录，记录每次合成的全流程状态。

字段名	类型	说明
id	String (UUID)	主键
digital_human_id	FK	关联的数字人 ID
audio_id	FK	关联的音频 ID
video_material_id	FK	关联的背景视频 ID
status	Enum	pending → generating_human → composing_video → completed / failed
temp_human_video_url	String	阿里云返回的中间产物（纯色背景口播视频）
final_video_url	String	最终成片 URL（OSS）
error_message	Text	失败报错日志
created_at	DateTime	创建时间
4. 核心业务模块详细逻辑
4.1 模块一：数字人管理（接入阿里云 wan2.2-s2v）
业务动作：用户上传一张照片 -> 系统保存到 OSS -> 调用阿里云检测接口校验图片。

阿里云接入具体细则：

检测接口：wan2.2-s2v-detect

目的：防止用户上传不合规图片导致后续扣费失败。

要求：图片分辨率宽高必须在 400 ~ 7000px 之间，格式为 jpg/png，必须是正面清晰单人照。

逻辑处理：若检测不通过，直接报错提示用户更换照片；通过则保存 active。

生成接口（异步）：wan2.2-s2v

入参：图片 URL + 音频 URL（来自音频模块）。

限制（致命）：输入的音频时长必须 < 20 秒。

并发限制（重要）：该模型在阿里云侧的同时处理任务数限制为 1。因此代码层必须实现任务队列（Queue），如果有多个合成请求，需排队逐一提交，防止 API 报 429 限流错误。

结果获取：提交后获得 task_id，采用指数退避轮询（间隔 5s, 10s, 20s...）查询结果。生成的结果视频 URL 24 小时内有效，需及时下载到本地临时目录或直接转存 OSS。

4.2 模块二：音频管理（接入阿里云 CosyVoice-v3-Flash）
业务动作：用户输入台词文本 -> 调用 TTS API -> 生成音频 URL 保存。

阿里云 TTS 接入细则：

推荐模型：cosyvoice-v3-flash（流式与非流式通用）。

灵活性体现：

支持 情感控制：在文本中插入标签，如 [开心]、[悲伤]、[激昂] 控制语调。

支持 声音克隆（进阶）：用户上传 5-20 秒干净人声，训练专属音色。

文本长度：单次合成最多支持 20000 字符，带货文案通常几百字，完全够用。

音频格式要求：生成后转为 MP3 格式，时长需控制在 20 秒以内（若文案过长，系统需自动截断或加速提示）。

（补充：用户也可选择本地上传音频文件，格式必须为 MP3/WAV，小于 15MB）

4.3 模块三：视频创作库管理（背景）
业务动作：用户上传已拍好的视频文件。

逻辑要求：

仅支持常见视频格式（MP4, MOV）。

系统自动读取该视频的元数据（时长、分辨率）。

存储策略：上传后转存至 OSS 供后续合成使用。

4.4 模块四：合成工作流引擎（云端 FFmpeg 画中画）—— 最重要的核心
当用户选择 [数字人 A] + [音频 B] + [视频 C] 点击合成后，后端触发以下全自动异步工作流：

步骤 1：发起 AI 生成

从数据库取出数字人图片 URL 和音频 URL。

调用阿里云 wan2.2-s2v 提交任务。

更新任务状态为 generating_human。

轮询等待（因并发限制为 1，若前面有任务需排队）。

步骤 2：获取中间产物

阿里云生成完成，返回 temp_human_video_url（纯背景说话视频）。

系统将此 URL 下载到云服务器的 临时目录（/temp/task_id/）。

步骤 3：云端 FFmpeg 无损合成（画中画）

输入源：

Input 0：视频创作库的背景视频（全屏）。

Input 1：刚下载的数字人口播视频（缩小）。

滤镜逻辑：

将数字人视频缩放至原尺寸的 30% ~ 35%。

覆盖位置：右下角（预留 20px 边距），或左下角（需用户配置）。

音频处理：保留数字人音频（Input 1），可选择性混入背景音乐。

字幕处理：若音频关联的 text_script 有值，利用 FFmpeg 的 subtitles 滤镜将字幕压入视频底部。

步骤 4：上传与清理

本地 FFmpeg 渲染完成后，将最终 output.mp4 上传至阿里云 OSS。

获取公网可访问的 final_video_url，更新任务状态为 completed。

清理：删除云服务器临时目录下的所有中间文件（防止磁盘占满）。

5. 关键约束、异常处理与注意事项
开发时请务必处理以下边界情况，否则系统极易崩溃：

5.1 阿里云 wan2.2-s2v 的“20 秒”魔咒
问题：音频不能超过 20 秒，否则 API 直接报错。

解决方案：在合成任务开始时，检查音频 duration。若 > 20秒，自动拒绝任务并提示用户“请将音频控制在 20 秒以内（约 80~100 字）”，或将长文案拆分成多段生成后再拼接（此功能较为复杂，初期建议直接限制文案字数）。

5.2 并发与限流
规则：阿里云同时只允许处理 1 个视频任务。

方案：必须自建 Bull Queue 或 Agenda 任务队列。当第二个用户发起合成时，系统返回 task_id 但状态为 pending，待第一个任务完成（completed）后，Worker 自动轮询拉起下一个任务。

5.3 云端存储空间（磁盘爆满）
数字人视频和背景视频均为 MP4，占用空间大。

必须：在 FFmpeg 合成成功的回调函数里，使用 fs.rm 强制删除 temp/task_id/ 整个文件夹。

5.4 背景视频与数字人视频时长不一致
如果背景视频很短（如 5 秒），数字人视频很长（如 10 秒）。

处理逻辑：FFmpeg 合成时，设置背景视频 stream_loop=-1（无限循环），使其总时长匹配数字人视频长度。

5.5 OSS 访问权限
所有上传的图片、音频、视频的 OSS Bucket 必须设置为公共读（Public Read），否则阿里云 wan2.2-s2v 和 FFmpeg 无法拉取文件（FFmpeg 只能读取公网 URL 或本地路径，建议先下载至本地）。

6. 预留扩展：MiniMax 接入（第二阶段）
为应对未来阿里云并发限制或音色需求，系统设计时应预留扩展接口。

数字人替代方案：MiniMax DigitalHuman-v1 模型。

调用地址：https://api.minimaxi.com/v1/video/generate

优势：支持音频时长 5~60 秒，比阿里云更长。

TTS 替代方案：MiniMax speech-2.8-hd。

优势：支持 7 种情感 精细化调节，多语言混合能力极强。

代码架构预留：在 services/ 目录下抽象出 IVideoProvider 和 ITTSProvider 接口类，将阿里云和 MiniMax 分别实现为 AliyunProvider 和 MiniMaxProvider，便于切换。
