## 微信支付从个人切换为企业

### 问题
结账页面仍显示个人收款二维码（收款人：刘春宇），未切换为企业微信支付。

### 根因
- `app/api/payments/checkout/route.ts` 仅在客户端显式传 `channel: "WECHAT_ENTERPRISE"` 时才走企业支付，前端没传，默认走个人收款。

### 修复
- `app/api/payments/checkout/route.ts`：企业支付配置存在时默认走 `WECHAT_ENTERPRISE`；响应中企业支付不再返回个人二维码/收款人。
- `lib/payments/wechat-pay-config.ts`：新增 `appId` 配置项，`isWechatPayConfigured()` 校验时要求 appid。
- `lib/payments/wechat-pay-client.ts`：`createNativeOrder` 使用 `cfg.appId` 而非空字符串。
- `.env.local`：新增 `WECHAT_PAY_APP_ID=` 占位，等待用户填写。

### 已完成（8月1日）
用户提供了服务号 appid `wx964d5580f3963853`，已填入 `.env.local` 的 `WECHAT_PAY_APP_ID`。企业微信支付配置现已完整。

## 注册验证码无效问题修复

### 问题
用户注册时输入 888888 始终提示"验证码无效"，但后端逻辑经 curl 测试完全正常。

### 根因
`MathCaptcha` 组件的验证码输入框没有提交按钮，只能按 Enter 提交。但按 Enter 会同时触发：
1. `handleVerify()` → 设置 captchaRef → setTimeout 调用 `send()` 发短信
2. 表单 `onSubmit` → 直接调用注册 API

注册请求先于短信发送到达后端，数据库里没有验证码记录，所以报"验证码无效"。

### 修复
- `components/auth/math-captcha.tsx`：
  - `handleKeyDown` 加 `e.preventDefault()` 阻止 Enter 触发表单提交
  - 新增"确认"按钮，用户可以直接点击提交验证码答案，不必按 Enter

### 验证
curl 测试完整流程（生成验证码 → 发送短信 → 注册）全部通过，两个手机号均注册成功。
