## 注册验证码无效问题修复

### 问题
用户注册时输入 888888 始终提示"验证码无效"，但后端逻辑经 curl 测试完全正常。

### 根因
`MathCaptcha` 组件的验证码输入框没有提交按钮，只能按 Enter 提交。但按 Enter 会同时触发：
1. `handleVerify()` → 设置 captchaRef → setTimeout 调用 `send()` 发短信
2. 表单 `onSubmit` → 直接调用注册 API

注册请求先于短信发送到达后端，数据库里没有验证码记录，所以报"验证码无效"。

### 修复
- `components/auth/math-captcha.tsx`：
  - `handleKeyDown` 加 `e.preventDefault()` 阻止 Enter 触发表单提交
  - 新增"确认"按钮，用户可以直接点击提交验证码答案，不必按 Enter

### 验证
curl 测试完整流程（生成验证码 → 发送短信 → 注册）全部通过，两个手机号均注册成功。

## 微信支付履约 bug 修复（8月5日）

### 问题
用户支付成功后积分未发放到账户。

### 根因
`app/api/payments/wechat/query/route.ts` 和 `app/api/payments/wechat/notify/route.ts` 两个路由都有两个 bug：
1. 在调用 `fulfillPaymentCheckout` 之前就把 `checkout.status` 改成了 `"PAID"`，但 `fulfillPaymentCheckout` 内部会检查 `status === "PAID"` 然后直接返回（认为已履约），积分从未发放
2. 调用签名错误——传了字符串 `checkout.id`，但函数期望对象 `{ checkoutId, confirmMode, confirmedByUserId, adminNote? }`

### 修复
- 去掉预先更新 `status=PAID` 的逻辑，由 `fulfillPaymentCheckout` 内部事务统一处理
- 修正调用签名，传入完整对象
- 已通过 admin-instant 接口为测试订单 `cmsg44wsa` 补发 1500 积分
